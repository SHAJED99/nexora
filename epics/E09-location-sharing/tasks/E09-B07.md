# E09-B07 · the delegation guard is not a guard

## The defect

`E09-T02` §4 makes one rule binding: *"Does not re-derive the LOCATION-OFF
precedence. Call `ConflictResolver.resolveLocationSharing`."* §8 names the
test that is supposed to hold that rule in place, and states its purpose in
the same sentence: *"asserts the value equals
`ConflictResolver.resolveLocationSharing(false, true)`, **so the delegation is
proven rather than coincidental**"*.

The shipped test
(`test/features/location/domain/location_visibility_policy_test.dart:181-199`)
ends with:

```dart
expect(
  ConflictResolver.resolveLocationSharing(false, true),
  isFalse,
);
```

That asserts a property of `ConflictResolver` alone. Nothing in it reads
`result`, and nothing ties it to the policy call fifteen lines above. It
passes identically whether `LocationVisibilityPolicy` delegates, inlines, or
never imports `ConflictResolver` at all.

The production code today **is** correct —
`lib/features/location/domain/location_visibility_policy.dart:79-80` really
does call the resolver. The defect is that nothing in the suite would notice
if it stopped.

## Repro

1. `git checkout epic_09` (verified at `18d658e`).
2. In `lib/features/location/domain/location_visibility_policy.dart`, replace
   the delegation with the inline re-derivation §4 forbids, and delete the
   now-unused import:
   ```dart
   final sharingAllowed = globalEnabled && peerEnabled;
   ```
3. `flutter test test/features/location/`

## Expected

`test_EARS_LOC_4_global_off_beats_peer_on` fails — that is the stated reason
§8 asked for the assertion.

## Actual

```
00:08 +78: All tests passed!
```

All 78 location tests pass, including the one named as the proof. The scope
fence §4 declares binding is unguarded, and `E09-T02`'s §9 self-review ticks
*"`ConflictResolver.resolveLocationSharing` is actually called, not inlined
(`location_visibility_policy.dart:69` — call site; **proven by**
`test_EARS_LOC_4_global_off_beats_peer_on` comparing the policy's reported
reason against the resolver's own output)"* on the strength of a comparison
the test does not make.

(Control probes from the same review, confirming the harness itself is sound:

Both failed for the right reason. Only the delegation guard is inert.)

## Severity

**S3** — nothing is broken for a user today; the call site is present and
correct, and the behaviour (`globalEnabled && peerEnabled`) is right either
way. The workaround is that the code happens to be correct. What is missing
is the regression guard for a rule `E09-T02` §2 justifies precisely by the
divergence risk: *"a second, private copy of a security precedence rule is how
the two copies diverge."* Not S2: no shipped behaviour is wrong, and
`FR-MSG-007`'s outcome is separately asserted by
`test_EARS_LOC_1_global_off_is_unavailable_reason_global_off`.

## Fix direction

Make the assertion depend on the policy's own output, e.g.

```dart
// The reason the policy reports must be the one implied by the resolver's
// verdict on the same two inputs -- not a standalone fact about the resolver.
for (final g in [true, false]) {
  for (final p in [true, false]) {
    final r = LocationVisibilityPolicy.evaluate(
      localState: RelationshipState.trusted,
      remoteState: RelationshipState.trusted,
      globalEnabled: g,
      peerEnabled: p,
    );
    expect(r.isVisible, ConflictResolver.resolveLocationSharing(g, p));
  }
}
```

Anything whose failure mode is "the resolver's verdict and the policy's
verdict disagree" is acceptable. A truth-table sweep over both inputs also
closes the untested `globalEnabled: false, peerEnabled: false` combination,
which no current policy test covers directly (only the multi-failure
precedence test at line 142 exercises it, and there `blocked` masks it).

Then correct `E09-T02` §9's self-review claim to cite the new test.

## Regression test (write it first)

The repro above **is** the regression test: with the fix in place, replacing
the delegation with `globalEnabled && peerEnabled` must fail
`test_EARS_LOC_4_global_off_beats_peer_on`. Restore verbatim, re-run green.

## What this fix does NOT do

- Does **not** change `lib/` at all. The production code is correct; only the
  test is inert. If the fix tempts an edit to
  `location_visibility_policy.dart`, that is the wrong fix.
- Does **not** change `ConflictResolver` or anything under
  `lib/features/messaging/`. `resolveLocationSharing` is E05-T05's and is
  correct.
- Does **not** touch the `notAuthorized`/`notConnected` precedence order or
  its documented deviation. That ordering was independently falsified as
  correct by two reviews; leave it and its doc comments alone.
- Does **not** add a `LocationSettingsRepository` test, a fixture, or a mock —
  the policy is pure and its test needs no database.
- Does **not** audit the other epics' tests for the same unfalsifiable shape.
  That belongs in `skills/retro` as the systemic half (this is now the second
  instance in E09 after `E09-T05`'s `fail()` guards, which is a recurrence and
  therefore a lesson-promotion trigger, not a one-off).
