# E09-B05 · three of five tasks were self-reviewed at the model level

## The defect

`AGENTS.md` rule 5: *"`reviewed_by` ≠ `executed_by` — **a different model**
reviews than implemented."* `agent/agents/reviewer.md` restates it without
room for interpretation: *"Independence comes from the **model routing**, not
from a second personality file."*

E09's five task files, frontmatter, side by side:

| Task | `executed_by` | `reviewed_by` | Rule 5 |
|---|---|---|---|
| E09-T01 | `claude-sonnet-5` | `claude-sonnet-5` (reviewer, independent session) | ❌ **same model** |
| E09-T02 | `claude-sonnet-5` | `claude-sonnet-5` (reviewer, independent session) | ❌ **same model** |
| E09-T03 | `claude-sonnet-5` | `claude-sonnet-5` (reviewer, independent session) | ❌ **same model** |
| E09-T04 | `claude-sonnet-5` | `claude-opus-5` (genuine cross-model, two rounds) | ✅ |
| E09-T05 | `claude-sonnet-5` | `claude-opus-5` (genuine cross-model, two rounds) | ✅ |

"Independent session" is the mitigation rule 5 explicitly declines to accept.
A fresh session of the same model shares the priors, the blind spots and the
failure modes that produced the code — which is the entire reason the rule
names the model and not the session.

**The three affected tasks are the epic's three `must` tasks**, including
`E09-T03`, which owns the encryption, the blocked-peer gate on both
directions, and the whole wire codec — the highest-consequence diff in the
epic.

## Repro
1. `git checkout epic_09`.
2. Read the `executed_by:` and `reviewed_by:` lines of each of
   `epics/E09-location-sharing/tasks/E09-T0{1..5}.md`.
3. Compare the model identifier on each side.

## Expected
Rule 5, and `harness.yaml`'s gate chain: task PR → review gate by a
different model → epic branch. `E09-T01`, `T02` and `T03` should each carry
a `reviewed_by:` naming a model that is not `claude-sonnet-5`.

## Actual
All three name `claude-sonnet-5`. The task files disclose the session
independence honestly and do not claim cross-model review — so this is a
routing miss by the orchestrator, not a false attestation by the builder or
the reviewer.

## The evidence that it mattered

This is not a paperwork finding. The outcomes separate cleanly along the
same line:

- **Three same-model reviews → zero findings.** `E09-T01`, `T02` and `T03`
  all have an empty §Feedback log ("(human feedback lands here)") and went
  straight to APPROVE in one round.
- **Two cross-model reviews → three real, falsified defects.** `E09-T04`
  round 1: an `S2` deterministic `ConcurrentModificationError` plus leaked
  Drift subscriptions in `watch()`, and an `S3` broken emit-on-listen
  contract for second listeners. `E09-T05` round 1: an `S2`-class test
  defect where four `fail()`-based negative guards were **unfalsifiable** —
  the thrown `TestFailure` was swallowed by `currentFix()`'s own
  `catch (_)`, so deleting the entire provider-off short-circuit left the
  suite green.
- **This sweep then found two more `S2` defects** (`E09-B01`, `E09-B02`)
  whose fix sites are `E09-T02`'s policy inputs and `E09-T03`'s single
  `deleteFix` call site — i.e. inside the diffs that got the same-model
  reviews.

A 0-findings review rate on the three highest-risk tasks and a 100%-findings
rate on the two correctly-routed ones is the rule earning its keep.

## Severity
**S2** — a merge gate that `AGENTS.md` calls non-negotiable did not actually
run on 60% of the epic, and the two defects this sweep found sit squarely in
the unreviewed diffs. No workaround: the review either happened against a
different model or it did not. Not S1: nothing is known-broken beyond B01/B02,
the suite is green (895/895), and the code that *was* cross-model reviewed is
demonstrably in good shape.

## Fix direction
**Re-review `E09-T01`, `E09-T02` and `E09-T03` against `skills/review`, with
a model that is genuinely not `claude-sonnet-5`** — a separate-session run
(Codex in its own CLI, zero shared context) is the strongest form and is
what `agent/agents/reviewer.md` recommends for exactly this class of diff.
Priority order by consequence:

1. **`E09-T03`** — encryption, the two-sided gate, the codec, the
   `handleWireFrame` drop paths. Run the security lens
   (`skills/review` §7 / `references/security.md`): this diff is
   crypto-adjacent state-machine code, and `E06-B04`'s forged-sender lesson
   is one it explicitly claims to have applied.
2. **`E09-T02`** — the four-condition policy and its precedence order, the
   file `E09-B01` proves had an unwatchable input.
3. **`E09-T01`** — the v15 migration and the `location_fixes` PK invariant.

Then update each file's `reviewed_by:`/`reviewed_at:`/`review_outcome:` to
name the real second model, and record any findings as further `E09-B*`
bugs. If a re-review returns APPROVE with no findings, say so plainly —
that is a clean result, not a wasted pass.

**Systemic half:** this belongs in `skills/retro` as a `L-process-*` lesson
with a concrete promotion path — a `make health` / `scheduler.py --validate`
check that fails when a task's `reviewed_by:` model identifier equals its
`executed_by:` model identifier. The rule is mechanically checkable, which
is exactly the retro ladder's "lesson → rule → hook" end state, and it is
the only fix that survives everyone forgetting.

## Regression test (write it first)
The check described above is the regression test, and it is a harness check
rather than a Dart test: assert that for every task file in `epics/**/tasks/`,
the model identifier in `reviewed_by:` differs from the one in
`executed_by:`. It must **fail on today's tree** naming `E09-T01`, `E09-T02`
and `E09-T03` (and should be run across every prior epic — this sweep did
not audit E01–E08 for the same pattern, and that audit is part of the fix).

## What this fix does NOT do
- Does **not** modify any file under `lib/`, `test/`, `android/` or
  `pubspec.*`. If a re-review finds a code defect, that defect gets its own
  `E09-B*` file and its own fence — this bug is the routing miss only.
- Does **not** revert, re-open or re-merge PRs #32, #35 or #38. The code is
  merged and green; what is missing is the second opinion, which can be
  obtained against the merged tree.
- Does **not** re-review `E09-T04` or `E09-T05`. Both were correctly routed
  and both already went two rounds.
- Does **not** change `AGENTS.md`, `harness.yaml` or the reviewer role file.
  The rule is already written correctly; it was not enforced.
- Does **not** implement the `make health` check itself — that is the retro's
  promotion step, recorded here so it has a reader.
