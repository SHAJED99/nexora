# E09-B12 · the globalOff > peerOff reason precedence has no regression guard

## The defect

`lib/features/location/domain/location_visibility_policy.dart:101-105`:

```dart
return LocationVisibility.hidden(
  !globalEnabled
      ? LocationUnavailableReason.globalOff
      : LocationUnavailableReason.peerOff,
);
```

`E09-T02` §5 documents this ordering as part of the contract, not an
implementation detail. The shipped behaviour is correct. But every test in
the suite that reaches this branch has already fixed one of the two inputs
before asserting the reason:

- `test_EARS_LOC_1_global_off_is_unavailable_reason_global_off` — global=F,
  **peer=T**.
- `test_EARS_LOC_1_peer_off_is_unavailable_reason_peer_off` — global=T,
  peer=F.
- `test_EARS_LOC_4_global_off_beats_peer_on` — global=F, **peer=T**.
- `location_read_model_test.dart` / `location_share_service_test.dart`'s own
  visibility helpers — both explicitly set `peerEnabled: true` before
  toggling global off, for unrelated reasons (isolating the assertion they
  actually care about).
- `E09-B07`'s own truth-table sweep (`policy_test.dart:208-235`) — iterates
  all four `(globalEnabled, peerEnabled)` combinations including
  `(false, false)`, but compares only `result.isVisible` against
  `ConflictResolver.resolveLocationSharing(g, p)`. `isVisible` is `false`
  either way the precedence is written, so the sweep cannot see this bug.

**No test anywhere evaluates `(globalEnabled: false, peerEnabled: false)`
and asserts `result.reason`.**

## Repro

1. `git checkout epic_09`.
2. In `location_visibility_policy.dart:101-105`, invert the ternary:
   ```dart
   return LocationVisibility.hidden(
     !peerEnabled
         ? LocationUnavailableReason.peerOff
         : LocationUnavailableReason.globalOff,
   );
   ```
3. `flutter test test/features/location/`

## Expected

Some test fails — the precedence order is supposed to be enforced.

## Actual

All 914 tests pass. Confirmed by manual exhaustive check against every
`globalOff`/`peerOff` assertion site in the tree (8 sites, enumerated in the
finding) — every one of them fixes `peerEnabled: true` before toggling
global off, or returns before reaching this branch at all (the `blocked`/
`!connected` early returns).

## Severity

**S3** — test-only. The shipped behaviour is correct and is exercised
end-to-end by `design/screens/chat-location.md`'s state 1 vs state 5
rendering without incident. What's missing is the regression guard: a
future refactor of these four lines (or a copy-paste into a sibling policy)
has no test failing to catch an inversion. Not S2: nothing is broken today.

## Fix direction

Extend `E09-B07`'s existing sweep at `policy_test.dart:208-235` to also
assert `result.reason` for each of the four combinations, not just
`isVisible` — e.g.:

```dart
for (final g in [true, false]) {
  for (final p in [true, false]) {
    final result = LocationVisibilityPolicy.evaluate(
      localState: RelationshipState.trusted,
      remoteState: RelationshipState.trusted,
      globalEnabled: g,
      peerEnabled: p,
    );
    expect(result.isVisible, ConflictResolver.resolveLocationSharing(g, p));
    if (!result.isVisible) {
      expect(
        result.reason,
        g ? LocationUnavailableReason.peerOff : LocationUnavailableReason.globalOff,
      );
    }
  }
}
```

Or add a standalone
`test_EARS_LOC_1_global_off_and_peer_off_reports_global_off` next to the
existing single-input reason tests, matching their style rather than
folding into the sweep. Either closes the gap; prefer whichever reads more
consistently with the surrounding tests.

## Regression test (write it first)

The repro above **is** the regression test: with the fix in place, the
ternary inversion in `location_visibility_policy.dart:101-105` must fail
the new/extended assertion. Falsify by making the swap, confirming red,
reverting, confirming green.

## What this fix does NOT do

- Does **not** change `location_visibility_policy.dart`. The production
  code is correct; only test coverage is missing.
- Does **not** touch `E09-B07`'s existing sweep test's `isVisible`
  assertions, `ConflictResolver`, or the `notAuthorized`/`notConnected`
  precedence order — both independently falsified as correct by prior
  reviews.
- Does **not** re-open `E09-B05` or `E09-B07`; this is a new, narrower gap
  those passes left behind, not a defect in either of their fixes.
