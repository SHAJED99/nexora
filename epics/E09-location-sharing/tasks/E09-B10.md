# E09-B10 · `share()` can throw, and its contract says it never does

## The defect

`E09-T03` §5: *"Returns, never throws, for every one of these — a refused
share is a normal outcome, not an exception."* The class doc on
`LocationShareOutcome` repeats it verbatim.

`location_share_service.dart:245-253` builds and serializes the frame
**above** the `try`:

```dart
final plaintext = LocationShareFrame(
  latitudeE7: (fix.latitude * 1e7).round(),
  longitudeE7: (fix.longitude * 1e7).round(),
  ...
).serialize();          // <-- line 251, outside the guard

try {                    // <-- line 253
  await _stack.prekeyExchange.ensureSession(peerDeviceId);
```

`LocationShareFrame.serialize()` calls `_requireInRange` on both coordinates
(`location_share.dart:135-136`) and throws
`AppFailure('location.malformed_share')`. `.round()` on a NaN or infinite
`latitude` throws `UnsupportedError` from the same region.

This mattered less while the only `LocationSource` was `E09-T03`'s test fake.
`messaging_stack.dart:399` now composes a real `PlatformLocationSource`
(`E09-T05`), so the values are supplied by a platform provider.

## Repro
Reviewer probe, run against `epic_09` @ `18d658e`, **failed**:
1. Build a `LocationShareService` whose `LocationSource` returns
   `LocationFix(latitude: 91.0, longitude: 0, capturedAtMs: 1)`.
2. Grant the peer full visibility (trusted, global on, peer on).
3. `await service.share('b')`.

## Expected
A returned `LocationShareOutcome` (§5). No exception crosses the boundary.

## Actual
```
PROBE B outcome=null thrown=AppFailure(location.malformed_share)
```

## Severity
**S3** — broken, with a workaround (the caller can wrap `share()` in its own
try/catch). Not S2: it needs a provider that reports an out-of-range or
non-finite coordinate, which a well-behaved platform provider does not. Not
S4: an uncaught `AppFailure` reaching a UI call site is a crash, not cosmetic.

## Fix direction
Move the frame construction and `serialize()` inside the existing `try`, or
validate the fix before building the frame. Note the two cases are not the
same outcome semantically: a fix the device itself cannot encode is closer to
`noFix` than to `transportFailed` — pick one deliberately and say which in
the doc comment. Consider also clamping `accuracyMmm` to
`0xFFFFFFFE` before `setUint32`, which silently truncates modulo 2^32 today
and can alias a very large accuracy onto the `0xFFFFFFFF` "not reported"
sentinel.

## Regression test (write it first)
`test_share_returns_rather_than_throws_on_unencodable_fix` — the probe above.
Must fail on today's tree (it does) and pass after.

## What this fix does NOT do
- Does **not** change the wire format, the range constants, or
  `deserialize`'s rejection behaviour.
- Does **not** touch `handleWireFrame`, the receive gate, the repository, or
  `messaging_stack.dart`.
- Does **not** change `PlatformLocationSource` (`E09-T05`) or add clamping on
  the provider side — the contract being broken is `share()`'s.
- Does **not** add a new `LocationShareOutcome` variant without saying so in
  the PR; §5's outcome set is part of the contract.
