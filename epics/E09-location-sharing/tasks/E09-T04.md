# E09-T04 · Last-known-location fallback + freshness

## 1. Goal
Give every future reader of a peer's location — starting with `E06-T18`'s
location card — one value that already says *how fresh it is*, so no surface
can accidentally present a twenty-minute-old position as live.

## 2. Business logic
- **`FR-LOC-005`** has two clauses and only one of them is optional:
  the system *may* show the last known location with a visible timestamp, and
  it **shall never represent stale location as live**. The SHALL NOT is what
  this task exists for. The way to make it unbreakable is to make the freshness
  a **required, non-null field of the value itself** — not a flag a caller
  might forget to read, and not a nullable field that defaults to "live".
- **Three outcomes, exactly matching what the design contract renders**
  (`design/screens/chat-location.md` states 2/3, 4 and 5):
  - `live` → the card's subtitle reads `Shared just now`
  - `lastKnown` → the subtitle reads `Last known · h:mm AM`, and the value
    **carries the timestamp**, because a `lastKnown` with no timestamp is
    precisely the violation
  - `unavailable` → the `Location unavailable` card, carrying the
    `LocationUnavailableReason` from `E09-T02` where one applies
- **Freshness is measured against `captured_at`** (the sender's measurement
  time), never `received_at`. A fix that arrived a moment ago but was measured
  half an hour earlier is stale. This is the whole reason `E09-T01` stores both.
- **The threshold is a named, injected constant, not a magic number** —
  `kLocationLiveWindow`, default **2 minutes**, injectable for tests. Two
  minutes is chosen as a *defensible default, not a specified one*: `spec/` sets
  no threshold and `chat-location.md` explicitly hands update frequency to E09.
  Recorded as `OQ-E09-T04-1` rather than presented as a requirement.
- **The policy still gates the read.** A fix may be stored and the peer may
  have since been blocked or turned off. `read()` re-evaluates
  `LocationVisibilityPolicy` and returns `unavailable(reason)` — a stored row
  is never evidence of permission (`chat-location.md`: "a rendered bubble is
  never evidence that sharing is permitted").
- **`unavailable` beats `lastKnown`.** If the policy fails, the age of the
  stored fix is irrelevant and must not leak through.

## 3. What this task does
- Creates `LocationReading` — a sealed/sum value with exactly the three cases
  above, where `lastKnown` structurally cannot exist without its `capturedAt`.
- Creates `LocationReadModel.read(peerDeviceId)` — the single read path a UI
  surface calls, combining the policy re-check, the stored fix and the
  freshness computation.
- Adds `LocationFixRepository.watchFix(peerDeviceId)` so a future surface can
  react to a newly received fix without polling (the same emit-on-listen shape
  `StorageSettingsRepository.watch()` established), and
  `LocationReadModel.watch(peerDeviceId)` layered on it.
- Tests the boundary of the live window from both sides, and every ordering
  between `unavailable`, `lastKnown` and `live`.

## 4. What this task does NOT do  ← the scope fence
- **Does not render anything, and does not contain a single user-facing
  string.** `Shared just now`, `Last known · h:mm AM` and `Location
  unavailable` are **design copy** owned by `design/screens/chat-location.md`
  and built by `E06-T18`; a domain model that formats copy makes the design
  gate unable to check it character for character. This task returns
  structured values and a `DateTime`, never a formatted string.
- **Does not format a timestamp.** No `intl`, no `h:mm a` pattern, no
  `toLocal().toString()`. The shape of the time is the contract's; the instant
  is this task's.
- **Does not add a dependency.**
- **Does not acquire, encrypt, send or receive anything** — T03 and T05.
- **Does not write to `location_fixes`** beyond nothing at all; this task is
  read-side only. The write path is `E09-T03`'s and stays there.
- **Does not add a "refresh" or "request location" action.** Asking a peer for
  a fresh fix is a new wire message and new scope (`OQ-E09-T03-1`).
- **Does not expire or delete stale rows.** A stale fix stays stored and is
  reported as stale; deleting it would lose the very fallback `FR-LOC-005`
  permits.
  **Correction (`E09-B02`, filed at the end-of-epic bug sweep):** this
  section previously read "Retention of these rows is `E08`'s policy
  surface, not this task's." That was false — `E08`'s `StorageItemKind`
  enumerates only `message`, `relayPayload`, `databaseFile` and four
  unwritten media kinds, and `StorageManager.runPass` scopes its executor to
  `{message}` alone (`lib/core/storage/storage_item.dart`,
  `storage_manager.dart`). Nothing in E08 has ever heard of
  `location_fixes`, and E08 is closed, so there is no live task the
  obligation could still land on. A stale-but-still-policy-visible fix has
  no owned retention policy and none is created by this correction (out of
  scope for both this task and `E09-B02`); a fix whose *visibility policy*
  no longer holds (blocked, unfriended, sharing turned off) is a different,
  permission-driven case, and is deleted by
  `LocationShareService.pruneFixesForNonVisiblePeers()` (`E09-B02`), not by
  any E08 retention pass.
- **Does not log a coordinate, an age, or a peer id** (E13 `EARS-DIAG-1`).

## 5. Contract

### Data — the read value
```dart
enum LocationFreshness { live, lastKnown }

sealed class LocationReading {}

final class LocationAvailable extends LocationReading {
  final double latitude;
  final double longitude;
  final double? accuracyM;              // null = sender reported none, never 0
  final DateTime capturedAt;            // ALWAYS present, both freshness cases
  final LocationFreshness freshness;    // non-null, required — FR-LOC-005's guard
  final DateTime staleAt;               // capturedAt + liveWindow — OQ-E09-T04-2:
                                         // lets a long-lived subscriber schedule its
                                         // own rebuild instead of holding a `live`
                                         // reading that silently ages into stale
}

final class LocationUnavailable extends LocationReading {
  final LocationUnavailableReason? reason;   // null = no fix has ever been received
}
```

> `capturedAt` is required on **both** freshness values, not only on
> `lastKnown`. A `live` reading that cannot say when it was captured cannot be
> re-checked by anything downstream, and the asymmetric shape is what tempts a
> caller into treating "no timestamp" as "now".

### Functions
```yaml
- signature: "const Duration kLocationLiveWindow = Duration(minutes: 2)"
  params: {}
  returns: "the default live/stale boundary"
  purpose: "one named constant, so the threshold is greppable and changeable in one place (OQ-E09-T04-1)"

- signature: "LocationReadModel({required LocationFixRepository fixes, required LocationSettingsRepository settings, required RelationshipRepository relationships, Duration liveWindow = kLocationLiveWindow, DateTime Function() clock = DateTime.now})"
  params: { liveWindow: "injectable so tests pin the boundary instead of sleeping" }
  returns: "the single read path for a peer's location"
  purpose: "FR-LOC-005 in one place, with the FR-LOC-003 re-check built in"

- signature: "Future<LocationReading> LocationReadModel.read(String peerDeviceId)"
  params: { peerDeviceId: "the peer whose location is being read" }
  returns: >
    LocationUnavailable(reason) when the visibility policy fails;
    LocationUnavailable(null) when the policy holds but no fix is stored;
    LocationAvailable(freshness: live) when clock() - capturedAt <= liveWindow;
    LocationAvailable(freshness: lastKnown) otherwise.
    Never throws for any of these — they are all normal outcomes
  purpose: "the one function a UI surface calls; FR-LOC-005's SHALL NOT is discharged by its return type"

- signature: "Stream<LocationReading> LocationReadModel.watch(String peerDeviceId)"
  params: { peerDeviceId: "as above" }
  returns: "emits the current reading immediately on listen, then on every stored-fix or settings change"
  purpose: "so a surface renders the true state on its first frame rather than an empty one"

- signature: "Stream<LocationFixRow?> LocationFixRepository.watchFix(String peerDeviceId)"
  params: { peerDeviceId: "the peer" }
  returns: "the peer's single row or null, emitting immediately on listen"
  purpose: "the reactive read this task layers on; the added method on an existing repository"
```

> **A `watch` stream does not re-evaluate freshness on the passage of time** —
> it emits on data change, so a `live` reading can silently age into staleness
> without a new event. That is a real limitation and it is stated here rather
> than papered over with a timer: the caller re-reads when it renders, and
> `read()` is always authoritative. See `OQ-E09-T04-2`.

## 6. Risks
- **The default-to-live bug.** Any code path that constructs a
  `LocationAvailable` without explicitly computing freshness — a copy-with, a
  test helper, a default parameter — reintroduces exactly what `FR-LOC-005`
  forbids. `freshness` is `required`; keep it required.
- **Comparing against `receivedAt`** produces a test suite that passes and a
  product that lies. The tests must construct a row where `capturedAt` and
  `receivedAt` differ across the boundary in opposite directions, or they
  cannot tell the two implementations apart.
- Boundary arithmetic: `age == liveWindow` exactly. Pick `<=` for live (as §5
  states) and test both `liveWindow` and `liveWindow + 1ms`.
- `clock()` in tests must be injected, not `DateTime.now()` with a sleep — a
  two-minute window is not sleepable.
- Returning `lastKnown` when the policy has failed leaks a position the peer
  revoked. `unavailable` is checked first, before the row is even fetched.

## Open Questions
- **OQ-E09-T04-1 — how old is "stale"?** `spec/` names no threshold and
  `chat-location.md` explicitly hands update frequency to E09. This task uses
  **2 minutes**, chosen as a defensible default rather than a specified one,
  and isolates it in one named constant. `FR-LOC-005` is satisfied at any
  threshold — the requirement is that stale is *labelled*, not that the
  boundary is a particular number — so this is important, not blocking.
  - **Status:** 🟢 answered
  - **Answer:** Approved — 2-minute live/stale window (`kLocationLiveWindow`)
    accepted as the shipped default.
  - **Answered by:** human (decision authority explicitly delegated to the
    agent for this session, 2026-09-04)
  - **Date:** 2026-09-04
- **OQ-E09-T04-2 — `watch()` does not re-emit on the passage of time.** A
  reading that is `live` when emitted becomes stale without any new event, so a
  long-lived subscriber can hold a `live` value that is no longer true. `read()`
  is always authoritative and a surface that re-reads on render is correct, but
  a surface that subscribes once and never re-reads would violate `FR-LOC-005`
  visually. Options: a ticking timer in the read model (cost: a timer per
  subscription), a `staleAt` instant on the reading so the *consumer* can
  schedule its own rebuild (cost: pushes the obligation outward but makes it
  explicit), or accept it and bind `E06-T18` to re-read on rebuild. Advisory:
  the `staleAt` instant — it keeps the obligation checkable and adds no timer.
  Named here with `E06-T18` as the affected consumer so the obligation has a
  reader rather than living only in this file.
  - **Status:** 🟢 answered
  - **Answer:** Approved — the `staleAt` instant. Added to `LocationAvailable`
    in this task's §5 contract; `E06-T18` should schedule its own rebuild off
    it rather than polling or holding a timer.
  - **Answered by:** human (decision authority explicitly delegated to the
    agent for this session, 2026-09-04)
