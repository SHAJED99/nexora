# E04-B31 · Don't let a stale cached UUID answer drop a Nexora peer

## 1. Root cause

`handleDeviceFound` (E04-T06/T07) registers a pending Nexora check and calls `fetchUuidsWithSdp()`. `handleUuidResult` used `pendingNexoraChecks.remove(address)` and decided on whatever `ACTION_UUID` arrived first. During an active inquiry, Android delivers the device's cached UUIDs immediately and the real SDP result later. For any device with a pre-existing cache that predates its Nexora discovery record, which is every peer bonded or seen before E04-T07, the first answer lacks the discovery UUID. The check is consumed and the peer is dropped. Before E04-T07 this was masked, because the same stale cache contained the generic SPP UUID the old filter accepted.

## 2. Fix

`handleUuidResult` now reads the pending check without removing it:

- A **negative** answer leaves the check pending, so a later fresh answer can still confirm it.
- A **positive** answer removes it identity-scoped (`remove(address, pending)`) and emits once.
- The existing `SDP_LOOKUP_TIMEOUT_MS` identity-scoped removal in `handleDeviceFound` still bounds the check's lifetime.

## What this task does NOT do

- Does not change the filter itself (`advertisesNexora`), what is published, or the timeout value.
- Does not fix SDP failures to a particular device (the Pixel -> Redmi page timeouts observed live). If no positive answer ever arrives, the peer is still not shown; that is E04-T07's intended fail-closed behavior.
- Does not add a Kotlin test harness (none exists in this project).

## 2. Definition of Done

- [x] A negative `ACTION_UUID` no longer consumes the pending check; a positive one does, identity-scoped
- [ ] `flutter build apk --debug` compiles clean
- [ ] Independent review (reviewed_by != executed_by)

## Open Questions

- OQ-E04-B31-1: if every SDP query to a peer fails (as the Pixel -> Redmi page timeouts did at times in this session), that peer still never appears in Discover. That is by design (E04-T07 fails closed), but on flaky links it can look like "Nexora doesn't see my friend". A future task could retry the SDP query once after inquiry ends.
