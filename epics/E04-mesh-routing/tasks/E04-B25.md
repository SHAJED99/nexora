# E04-B25 · Dashboard preview uses persisted plaintext

## 1. Goal

Apply E04-B18's already-reviewed pattern to the one remaining preview
call site: `DashboardController._resolvePreview` reads
`Message.plaintextPayload` when present and only falls back to decrypting
`ciphertext` for legacy rows written before that column existed.

## 2. Background

This is the root cause of the `InvalidKeyIdException - No such one-time
prekey` seen repeatedly in live testing. An earlier investigation (this
session) attributed it to a replayed frame and concluded it was already
handled; the live repro above disproves that. The inbound pipeline
decrypts once, correctly. The error comes from the Dashboard decrypting
the same stored PreKeySignalMessage a second time. A second decrypt is
also not side-effect free (session record reload/store), so it is removed,
not just silenced.

## What this task does NOT do

- Does not change `ConversationsController` or `ChatController` (already fixed by E04-B18).
- Does not backfill `plaintext_payload` for legacy rows (E04-B18's deliberate decision).
- Does not patch `libsignal_protocol_dart`'s unawaited future in `processV3` (third-party dependency; rule 6).
- Does not touch the conversation-id divergence found in the same session (that is E04-B26).
