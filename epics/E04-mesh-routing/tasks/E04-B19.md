# E04-B19 · Show this device's own Bluetooth name on the Devices screen

## 1. Goal

Let a user pairing two phones answer "which name in my Bluetooth settings
is THIS phone?" from inside the app, instead of needing to separately open
Android's own Bluetooth settings.

## 2. Business logic

FR-DISC-001 (device discovery). Nothing in the spec requires this
specific display; it is a usability gap a human found live, filed and
approved directly (matching this session's `2026-09-05`/`2026-09-06`
standing autonomy grant for a human-directed, non-foundational UI
addition). Only the device's **name** is shown, deliberately never its
Bluetooth **address**: `E04-B17`/`E04-B18`'s own investigation found live
evidence that a raw Bluetooth address read back from the OS on this class
of device can be a generic, non-unique masked placeholder rather than a
real per-device MAC -- showing it to a user as "your device's address"
would be actively misleading. The device NAME is what Android's own
pairing UI on the OTHER phone actually shows, so it is the only value
that helps a user complete a real pairing.

## 3. What this task does

- New Pigeon host method `String getLocalDeviceName()`
  (`pigeons/transport.dart`, regenerated via `dart run pigeon`).
- `BluetoothTransport.kt`: implements it via `adapter?.name`, falling back
  to a fixed, clearly-labeled placeholder (`"This device (Bluetooth
  unavailable)"`) when the adapter is null/disabled -- never throws, never
  returns an empty string.
- `LoopbackTransport.kt`: a fixed, documented loopback-double value (no
  real adapter to query), matching this file's own existing pattern for
  every other native-only field (see its `bonded` doc comment from
  `E04-B17`).
- `TransportApiHost.kt`: delegates to `bluetooth.getLocalDeviceName()`.
- `TransportService.getLocalDeviceName()`: thin Dart facade, same shape as
  every other passthrough call in this file.
- `devices_view.dart`: a new, derived subtitle line under the existing
  "Manage paired and nearby devices." text (element 5), reading
  "Visible to nearby devices as: <name>" -- reuses the existing
  `devicesSectionSubtitle` token, no new visual language. Logged as
  `design/gaps.md` GAP-043 (derived, human-approved 2026-09-13, same
  precedent as `GAP-042`).

## 4. What this task does NOT do

- Does NOT display or expose this device's Bluetooth **address** anywhere
  -- see §2's reasoning; a masked/non-unique value has no legitimate
  display use here.
- Does NOT add a way to CHANGE the device's Bluetooth name from inside the
  app (that is Android's own Bluetooth settings' job) -- read-only
  display only.
- Does NOT touch `resolveDeviceId`, `isBonded`, or any other existing
  address-resolution logic -- this is a brand-new, independent read-only
  query, not a change to how peers are identified.

## 5. Definition of Done

- [x] `getLocalDeviceName()` exists Pigeon-to-Dart, implemented on both
  `BluetoothTransport` and `LoopbackTransport`.
- [x] Devices screen shows the device's own name.
- [x] Full test suite green, `flutter analyze` clean, `flutter build apk`
  succeeds (native Kotlin changes aren't caught by `analyze`/`test`
  alone -- `E04-B17`'s own lesson).
