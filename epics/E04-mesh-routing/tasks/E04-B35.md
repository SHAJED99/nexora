# E04-B35 · Detect a silently dead Bluetooth link with a native keepalive

## 1. Goal
When the phone at the other end of a Bluetooth link vanishes without a clean close (Bluetooth switched off, walked out of range, battery died), Nexora notices within about 30 seconds and treats the link as disconnected.

## 2. Business logic
- FR-ROUTE-009: when a route fails, the system searches for alternatives or queues/retries. That only starts once the failure is known; today a silent drop is never known.
- FR-UI-004: the default view says "You're connected" only when that is true. E04-B34 already clears the Dashboard on `DISCONNECTED`; this task makes sure `DISCONNECTED` actually arrives.
- NFR-BATT-001: keep extra traffic minimal. A keepalive is a 4-byte frame, sent only on a link that has been idle in the outbound direction.
- **Why native, not a Dart control message** (ADR-0004: system-sensitive transport behaviour stays in native Android):
  - The read loop, the sockets and `DISCONNECTED` all live in `BluetoothTransport`.
  - A Dart-level ping would add a new `kControlKind`, go through encryption and routing, and cost a Pigeon round trip every few seconds, just to learn something the transport can see directly.
- **Wire format:** the existing framing is a 4-byte big-endian length prefix followed by that many bytes. A keepalive is a frame with length `0` and no payload. No new marker, no new field.
- **Backward compatibility** (checked in code):
  - A peer on an older build receives the empty frame through its read loop as `onDataReceived(deviceId, [])`.
  - Dart's `RelayPacketFrame.deserialize` throws `FormatException('empty buffer...')` for an empty buffer (`relay_packet_frame.dart:195-198`).
  - `InboundPipeline._handleBuffer` catches exactly that, increments `counters.malformed`, and returns (`inbound_pipeline.dart:919-923`).
  - So an old peer is unharmed. Its `malformed` counter rises by one per keepalive, which is disclosed, not fixed here.
- **Arming rule:** the silence watchdog for a link only arms after that peer has sent at least one keepalive, which proves it runs a build that sends them. A peer on an older build never sends one, so an idle old peer is never wrongly disconnected.

## 3. What this task does
- **Receive:** in `startReadLoop`, a frame with `length == 0`:
  - is consumed as a keepalive and never forwarded as `onDataReceived`;
  - marks the peer as keepalive-capable;
  - like every other frame, updates that link's last-received time.
- **Send:** a single background scheduler checks all open links every `KEEPALIVE_INTERVAL_MS`. For each link with no outbound write in the last interval, it writes one empty frame using the same `synchronized(socket)` framing as `writeFrame`.
  - The write runs with the same bounded wait as `send()` (`SEND_TIMEOUT_MS`).
  - A failed or timed-out keepalive write calls `disconnect(deviceId)`, which emits `DISCONNECTED`.
- **Watchdog:** on the same tick, a link whose peer is keepalive-capable and has sent nothing for `LINK_SILENCE_TIMEOUT_MS` is closed with `disconnect(deviceId)`.
- **Lifecycle:**
  - Per-link state (last sent, last received, keepalive-capable) is created when a socket is registered (outbound connect, post-bond connect, accept).
  - It is removed in `disconnect()`, in the read loop's remote-drop exit, and in `release()`.
  - The scheduler is stopped in `release()`.

## 4. What this task does NOT do
- Does not change Dart code, the Pigeon schema, `RelayPacketFrame`, or any `kControlKind`. It adds no Dart-side ping or ack.
- Does not add a Kotlin test harness (none exists in this project). Verification is compile plus live hardware (§8).
- Does not change `connect()`, `doConnect`/`doConnectAfterBond` retry behaviour (E04-B32/B33), or E04-B28's scan-based lost events.
- Does not silence old peers' `malformed` counter, and does not add a version handshake.
- Does not make the intervals user-configurable or battery-adaptive (E10-T10's adaptive policy may tune them later).
- Does not fix OQ-E04-B32-3 (two sockets registered for the same peer).
- Does not touch `LoopbackTransport`.

## 5. Contract

### Functions / constants (in `BluetoothTransport`, next to `LENGTH_PREFIX_BYTES` / `MAX_FRAME_BYTES` / `SEND_TIMEOUT_MS`)
```yaml
- signature: "private const val KEEPALIVE_INTERVAL_MS = 10_000L"
  purpose: "how often an outbound-idle link gets an empty keepalive frame"
- signature: "private const val LINK_SILENCE_TIMEOUT_MS = 30_000L"
  purpose: "how long a keepalive-capable peer may send nothing before the link is declared dead; 3x the interval, so one or two late frames do not drop a healthy link"
- signature: "private fun sendKeepalive(deviceId: String, socket: BluetoothSocket)"
  params: { deviceId: "the open link's id", socket: "its registered socket" }
  returns: "Unit — on write failure or timeout calls disconnect(deviceId)"
  purpose: "write one zero-length frame with the same framing lock and bounded wait as send()"
- signature: "private fun keepaliveTick()"
  returns: "Unit"
  purpose: "for each open link: send a keepalive if outbound-idle; disconnect if a keepalive-capable peer has been silent past LINK_SILENCE_TIMEOUT_MS"
```

### Wire format
- Keepalive = `00 00 00 00` (length prefix 0, no payload). Every other frame is unchanged.

## 6. Risks
- **A blocking write on a dead link.** `OutputStream.write` can block on a link that is already gone. The keepalive write must use `send()`'s bounded-wait pattern, or the scheduler thread wedges and no link is ever checked again.
- **One tick can stall on several dead links** (plan review nit). Keepalive writes are serial with a bounded wait each, so a tick that finds N outbound-idle links can take up to N × `SEND_TIMEOUT_MS` (3 s each) before it reaches the silence checks. That is acceptable for this mesh's expected handful of peers. Revisit if peer counts grow, for example by running the silence checks before the writes, or writing in parallel.
- **Races with `send()`.** Keepalive and data writes must share `synchronized(socket)`, or their bytes interleave and desync the reader. That is the same reason `writeFrame` already locks.
- **Stale per-link state.** State keyed by device id must be removed on every teardown path, or a reconnect inherits "silent for 40 minutes" and is dropped at once. Clear it by identity, like `openSockets.remove(deviceId, socket)`.
- **Two sockets for one peer** (OQ-E04-B32-3). Track state per socket, not only per device id, so a keepalive from the surviving socket does not keep a dead one alive.
- **Battery.** At 4 bytes every 10 s per idle link, sent only when nothing else was sent, the cost is negligible. Still name it in the PR (NFR-BATT-001 has no target).
- **Old-peer noise.** An old peer's `malformed` counter rises by 6 per minute per idle link. It is harmless, but visible in any diagnostics that show that counter.

## 8. Acceptance criteria (EARS) + test plan
- **EARS-TRANSPORT-4**: WHEN a keepalive-capable peer sends no frame for `LINK_SILENCE_TIMEOUT_MS`, the system SHALL close the link and emit `DISCONNECTED` for it. (FR-ROUTE-009)
- **EARS-TRANSPORT-5**: WHEN an open link has had no outbound write for `KEEPALIVE_INTERVAL_MS`, the system SHALL send one zero-length frame on it. (FR-ROUTE-009, NFR-BATT-001)
- **EARS-TRANSPORT-6**: WHEN a zero-length frame is received, the system SHALL NOT deliver it as application data. (FR-ROUTE-003)
- **EARS-TRANSPORT-7**: IF a peer has never sent a keepalive, THEN the system SHALL NOT close its link for silence. (backward compatibility)
