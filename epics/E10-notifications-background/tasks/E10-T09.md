# E10-T09 · Power-state signals

## 1. Goal
Let Dart *see* the power environment it is running in — Doze, Battery Saver,
background restriction, screen lock — so `E10-T10` can adapt to it instead of
guessing.

## 2. Business logic
- **EARS-PLAT-1 / FR-PLAT-002** requires the system to "account for Android
  Doze, Battery Saver, background execution restrictions, app process
  termination and screen lock". Accounting for something starts with being
  able to observe it. Today nothing in the codebase can.
- **FR-PLAT-003 + ADR-0004**: these are system queries and system broadcasts —
  native, behind the Pigeon interface `E10-T08` created.
- **This task observes and reports. It changes no behaviour.** Nothing in the
  app reacts to these signals until `E10-T10`. Split this way deliberately:
  the reporting half is testable and low-risk, the reacting half is a policy
  decision with battery consequences.
- **`E04-T03a.md:97-98` deferred Doze handling to "T03b/T03c's concern" and
  neither built it** — a grep of the whole E04 epic for `Doze` returns only
  those two lines. This task is where Doze first becomes observable in this
  codebase at all; `E10-T10` §4 records what it does and does not do about
  the Bluetooth read loops.

## 3. What this task does
- Extends `pigeons/background.dart` with a `PowerState` class, a
  `powerState()` host method and an `onPowerStateChanged` event; regenerates
  both files.
- `PowerStateMonitor.kt` — reads `PowerManager.isDeviceIdleMode`,
  `isPowerSaveMode`, `ActivityManager.isBackgroundRestricted`,
  `PowerManager.isIgnoringBatteryOptimizations`, and `KeyguardManager`/screen
  state; registers receivers for `ACTION_DEVICE_IDLE_MODE_CHANGED`,
  `ACTION_POWER_SAVE_MODE_CHANGED`, `ACTION_SCREEN_ON/OFF` and
  `ACTION_USER_PRESENT`, emitting `onPowerStateChanged` on each. Registered
  with `RECEIVER_NOT_EXPORTED` (these are protected system broadcasts —
  the same posture `BluetoothTransport` uses).
- `BackgroundApiHost.kt` — delegates `powerState()` to the monitor;
  registers/unregisters the monitor in the existing attach/detach path.
- `power_state.dart` — the Dart model + `BackgroundService.powerState` /
  `powerStates` stream; `background_stub.dart` gains a settable power state
  so `E10-T10` is testable without a device.

## 4. What this task does NOT do
- Does **not** change any app behaviour based on these signals — no tick
  interval change, no discovery suppression, no notification. `E10-T10`.
- Does **not** request `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`. It **reads**
  `isIgnoringBatteryOptimizations` (a query, no permission) but never prompts
  — ADR-0007 §S2 / `OQ-E10-4`.
- Does **not** acquire a wake lock, `WAKE_LOCK` permission, or an alarm.
- Does **not** add any permission to the manifest at all. Every value here is
  readable without one; if an implementer finds one that is not, that is an
  Open Question, not a manifest edit.
- Does **not** touch `.../transport/`, `BluetoothTransport.kt`, or the
  Bluetooth read loops.
- Does **not** persist power state or log it with a timestamp trail — a
  device-idle history is a behavioural fingerprint.

## 5. Contract

### Pigeon schema additions (`pigeons/background.dart`)
```dart
class PowerState {
  bool deviceIdle;             // Doze
  bool powerSaveMode;          // Battery Saver
  bool backgroundRestricted;   // per-app background restriction
  bool ignoringBatteryOptimizations;
  bool screenLocked;
}

// added to BackgroundApi
PowerState powerState();

// added to BackgroundEventsApi
void onPowerStateChanged(PowerState state);
```

### Functions
```yaml
- signature: "BackgroundService.powerState() -> Future<PowerState>"
  returns: "a snapshot; on an API level lacking a signal the field is false, never null"
  purpose: "One-shot read for startup"

- signature: "BackgroundService.powerStates -> Stream<PowerState>"
  returns: "broadcast; emits on every system transition, de-duplicated on equal states"
  purpose: "What E10-T10 subscribes to"

- signature: "PowerStateMonitor.register(Context) -> Unit / unregister() -> Unit"
  purpose: "Receiver lifetime tied to the existing host attach/detach — no leak"

- signature: "BackgroundStub.emitPowerState(PowerState state) -> void"
  purpose: "Test lever; without it E10-T10 has no hardware-free test"
```

## 6. Risks
- **API-level gaps.** `isDeviceIdleMode` is API 23+, `isBackgroundRestricted`
  API 28+. Missing signals must default to `false` (the permissive reading),
  never crash, and never be reported as `true` by accident — a spurious
  "Doze" makes `E10-T10` throttle a device that is wide awake.
- Receivers must be unregistered on detach or every hot restart leaks one.
- Broadcast storms: `ACTION_SCREEN_ON/OFF` fire often. De-duplicate equal
  states before emitting, or `E10-T10` recomputes policy for nothing.
- These signals are **not** a substitute for observing that the service was
  killed — an OEM killer produces no broadcast at all. `E10-T08`'s
  `ServiceState.stoppedBySystem` is the signal for that; don't conflate them.

## 8. Acceptance criteria (EARS) + test plan
- **EARS-PLAT-10**: WHEN the device enters or leaves Doze, Battery Saver,
  background restriction or screen lock, the system SHALL emit a
  `PowerState` reflecting the new value. (FR-PLAT-002, FR-PLAT-003)
- **EARS-PLAT-11**: IF a signal is unavailable on the running API level,
  THEN the system SHALL report it as `false` and SHALL NOT throw; and equal
  consecutive states SHALL NOT be re-emitted. (FR-PLAT-002)

### Tests
- `test_EARS_PLAT_10_state_change_emits` (× each of the four flags)
- `test_EARS_PLAT_11_duplicate_state_not_reemitted`
- `test_EARS_PLAT_11_missing_signal_reads_false`
- Kotlin proven by compile + manual; no mock-only Kotlin test.

### Manual
1. `adb shell dumpsys deviceidle force-idle` → a `deviceIdle: true` event.
2. `adb shell settings put global low_power 1` → `powerSaveMode: true`.
3. Lock the screen → `screenLocked: true`; unlock → `false`.
