# E10-T10 · Adaptive background policy

## 1. Goal
Close the loop: start the service when the app backgrounds, let the one
existing tick keep running while it is closed, slow that tick down when the
OS says the device is asleep — and prove the retention pass runs with nobody
looking.

## 2. Business logic
- **EARS-PLAT-1 / FR-PLAT-002**: "account for Doze, Battery Saver, background
  restrictions, process termination and screen lock." `E10-T09` made those
  observable; this task is the *accounting*.
- **NFR-SEC-001 / `E06-T06.md:382-384`**: "with the app closed, nothing
  forwards and nothing reclaims." `reclaimPayloads()` is the third-party
  ciphertext retention guarantee. Making it run while the app is closed is a
  **separate acceptance criterion with its own test** (EARS-PLAT-14), not a
  side effect of EARS-PLAT-12 — the obligation was raised as its own item and
  is discharged as its own item.
- **The one-tick invariant** (`E08-T06.md:119-120`, `:127-131`): this task may
  change the tick's *interval*, and nothing else. No reordering of
  `processQueue`/`sweepExpired`/`reclaimPayloads`, no change to the
  re-entrancy coalescing, no second driver, no isolate. The storage pass E08
  appended keeps its own throttle.
- **NFR-BATT-001 is a trade-off, not a target** — "battery efficiency shall
  never override reliability or communication requirements", and
  `[NEEDS NUMBER]`. The inherited 60 s floor is an endorsed *guess*
  (`E06-T06.md:528-534`: nothing has ever been measured). This task
  re-justifies it rather than inheriting it silently, and states plainly what
  it did and did not measure.
- **Doze suppression of discovery** is the one behavioural concession worth
  making: `BluetoothAdapter.startDiscovery()` during Doze burns radio for
  results the OS will not deliver anyway.

## 3. What this task does
- `background_policy.dart` — `BackgroundPolicy`: pure function from
  `(PowerState, ServiceState, AppLifecycleState)` to a
  `BackgroundPlan { Duration tickInterval, bool discoveryAllowed }`. Fully
  unit-testable, no I/O. The cadence table lives here and nowhere else.
- `messaging_coordinator.dart` — make `_tickInterval` **settable at runtime**
  via one new method that reschedules the existing `Timer.periodic`. That is
  the entire change to this file: no new work in the tick, no reordering, no
  new state.
- `bindings.dart` — a `WidgetsBindingObserver` that starts
  `BackgroundService` when the app is backgrounded and stops it when it
  returns to the foreground; subscribes to `powerStates` and
  `BackgroundService.state`, applies each `BackgroundPlan` by setting the
  coordinator's interval and gating `TransportService.startDiscovery`; and
  reconciles after a `stoppedBySystem` event or a cold start by calling
  `MessagingCoordinator.reconcileQueuedMessages()` once.
- Discovery gating goes through the existing `TransportService` API — no
  change to `.../transport/` or any native file.

## 4. What this task does NOT do
- Does **not** add a `Timer`, `WorkManager` job, isolate, alarm or any second
  periodic driver. Setting the existing timer's interval is the mechanism.
- Does **not** change what the tick *does*: no reordering, no new step, no
  change to re-entrancy coalescing, no change to E08's storage-pass throttle.
- Does **not** change `BluetoothTransport.kt`, the read loops, or any native
  transport file. **What happens to an open RFCOMM socket and its blocking
  read thread during Doze is genuinely unhandled and unverifiable here**
  (`E04-T03a.md:97-98` deferred it to T03b/T03c and neither built it, and no
  hardware is installable in this environment) — carried as `OQ-E10-8`, not
  quietly implemented against a guess.
- Does **not** request a battery-optimisation exemption, add
  `RECEIVE_BOOT_COMPLETED`, or add background location (`OQ-E10-4`,
  `OQ-E10-5`, `OQ-E10-7`; ADR-0007 §S2/S3).
- Does **not** add a dashboard background-status indicator or connectivity
  alerts. `E06-T12.md:116-117` fenced those to E10, but `design/screens/
  dashboard.md` is an **approved contract with no such element** — adding one
  needs a `design/gaps.md` entry and human approval (rule 2). `OQ-E10-9`.
- Does **not** claim an NFR-BATT-001 outcome that was not measured.
- Does **not** change the 60 s foreground floor. Only the background/idle
  intervals are new.

## 5. Contract

### Functions
```yaml
- signature: "BackgroundPolicy.plan({required PowerState power, required ServiceState service, required AppLifecycleState lifecycle}) -> BackgroundPlan"
  returns: "{ Duration tickInterval, bool discoveryAllowed }"
  purpose: "The whole cadence decision, pure and testable, in one place"

- signature: "MessagingCoordinator.setTickInterval(Duration interval) -> void"
  params: { interval: "the new floor; must be > Duration.zero" }
  returns: "void — reschedules the existing Timer.periodic; a tick in flight is not cancelled"
  purpose: "The ONLY change this task makes to the coordinator"

- signature: "BackgroundLifecycleObserver.start() / stop() -> void"
  purpose: "Composition-root wiring: lifecycle -> service start/stop -> policy -> interval + discovery"
```

Cadence table (the proposal a reviewer checks, not a measurement):
| condition | tickInterval | discoveryAllowed |
|---|---|---|
| foreground | 60 s (unchanged — E06-T06's human-endorsed floor) | yes |
| background, service running, screen on | 60 s | yes |
| background, screen locked | 120 s | yes |
| Battery Saver on | 300 s | no |
| Doze (`deviceIdle`) | 300 s | **no** |
| background restricted | 300 s | no |
| service `stoppedBySystem` | foreground value (nothing is running anyway) | yes |
Most-restrictive condition wins when several hold. **Every number above
except 60 s is an unmeasured default**, chosen to be conservative; they are
listed here so the human can change one number in one table.

## 6. Risks
- **`setTickInterval` mid-tick.** Rescheduling while a tick is in flight must
  not cancel it, double it, or defeat the re-entrancy coalescing that
  `E06-T06`'s reviewer already falsified assumptions about once. Test the
  in-flight case explicitly.
- **The lifecycle observer is where a duplicate service start lives.**
  `paused` → `resumed` → `paused` in quick succession must not leave two
  starts outstanding; `BackgroundService.start()` is idempotent but the
  observer should not rely on that alone.
- Suppressing discovery in Doze means the mesh finds nobody while idle. That
  is the intended trade-off (NFR-BATT-001) and it is also a *reliability*
  reduction the NFR says must never be overridden — which is exactly why the
  table is proposed rather than assumed. Flag it for the human.
- A cold start after `stoppedBySystem` must reconcile the queue exactly once.
  Reconciling on every resume is wasteful; never reconciling loses messages.
- `reclaimPayloads()` running unattended touches retention — assert it ran,
  don't infer it from the tick count.

## 8. Acceptance criteria (EARS) + test plan
- **EARS-PLAT-12**: WHEN the reported power state changes, the system SHALL
  apply the corresponding tick interval, and SHALL NOT create any additional
  periodic driver. (FR-PLAT-002, NFR-BATT-001)
- **EARS-PLAT-13**: WHILE the device is in Doze or Battery Saver, the system
  SHALL NOT start peer discovery, and SHALL resume it when the condition
  clears. (FR-PLAT-002)
- **EARS-PLAT-14**: WHILE the app is backgrounded and the foreground service
  is running, the system SHALL continue to run the coordinator tick,
  including `reclaimPayloads()`. (FR-PLAT-001, NFR-SEC-001)

### Tests
- `test_EARS_PLAT_12_doze_lengthens_interval` / `_battery_saver_` /
  `_screen_locked_` / `_foreground_restores_60s`
- `test_EARS_PLAT_12_no_second_timer_created` — assert exactly one active
  periodic timer after a full lifecycle + power-state sequence
- `test_EARS_PLAT_12_interval_change_during_inflight_tick_is_safe`
- `test_EARS_PLAT_13_discovery_suppressed_in_doze` /
  `test_EARS_PLAT_13_discovery_resumes_on_doze_exit`
- `test_EARS_PLAT_14_reclaim_runs_while_backgrounded` — assert
  `reclaimPayloads` was invoked with the app in `paused` and the service
  `running`; this is the NFR-SEC-001 proof and must not be folded into
  another test
- `test_EARS_PLAT_14_reconcile_runs_once_after_stopped_by_system`

### Manual
1. Background the app; confirm ticks continue (log/counter) and the ongoing
   notification is present.
2. `adb shell dumpsys deviceidle force-idle` → interval lengthens, discovery
   stops. Release → both restore.
3. Kill the process; on restart, exactly one reconcile runs.
4. Record any battery/wake-count observation, or state explicitly that none
   was possible.
