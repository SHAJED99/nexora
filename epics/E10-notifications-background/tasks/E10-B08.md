# E10-B08 · An em-dash typo makes the manifest invalid XML

## The defect
`AndroidManifest.xml:74` (pre-fix), inside the `BootReceiver` comment added by
E10-B01:
```
cross-UID broadcast at all -- Android's own boot-receiver docs
```
XML 1.0 forbids `--` anywhere inside a comment body (only the closing `-->`
may contain it). AAPT2's manifest merger enforces this strictly and fails the
whole build — `flutter build apk` (debug or release) cannot succeed while
this string is present, which means no Kotlin-touching change in this epic
(B01 itself, T08, T09, B04) has actually been proven against a real manifest
merge since B01 landed; every one relied on `gradlew :app:compileDebugKotlin`
or Dart-side tests instead, exactly per this defect's own severity note below.

## Repro
```
cd android && ./gradlew :app:processDebugManifest
```
fails with an XML parse error at the line/column of the `--`.

## Expected
Valid XML; `processDebugManifest` / `flutter build apk --debug` succeeds.

## Actual
Manifest merge fails. Confirmed independently (not just taking the B04
builder's word): re-scanned `AndroidManifest.xml` with a small script that
walks every `<!--...-->` span and checks the body for `--`; found exactly one
match, at the reported location, before making any edit.

## Severity
**S2** — blocks `flutter build apk` for the entire app, on every branch that
has pulled E10-B01 (`e62f91f`), which is `epic_10` and everything built on
top of it since. Not S1: no runtime behavior is affected (the string never
reaches a device — it fails at build time, loudly, every time).

## Priority
**P1** — set under the decision authority explicitly delegated by the human
for this session. A one-character-class fix that restores the ability to
build the app at all outranks everything else still open in this epic.

## Fix direction
Replace the offending `--` with a semicolon (`;`) — matches the rest of the
same comment's punctuation style and needs no rewording beyond that.

## Regression test (write it first)
A test that reads the manifest and asserts no `<!--...-->` span contains the
literal substring `--` anywhere before its closing `-->`. Must fail on the
pre-fix manifest (one violation) and pass after.

## What this fix does NOT do
- Does not touch any other manifest attribute, element, or the `BootReceiver`/
  `ForegroundMeshService` declarations E10-B01 already fixed.
- Does not attempt a general XML-validity checker beyond the specific `--`
  rule that broke the build; that is out of scope for a one-line typo fix.
