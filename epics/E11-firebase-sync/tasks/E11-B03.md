# E11-B03 · T06's `files:` fence and its §3 deliverables contradict each other

## The defect

`E11-T06`'s `files:` fence lists exactly six paths:

```yaml
create: [ lib/core/services/device_directory_service.dart,
          test/core/services/device_directory_service_test.dart ]
update: [ lib/core/services/firebase_paths.dart,
          lib/core/services/firebase_boundary.dart,
          database.rules.json,
          docs/firebase-schema.md,
          test/core/services/firebase_rules_test.dart ]
```

Its §3, however, requires:

> Wires `publish` into `IdentityService.ensureSignedPreKey`,
> `IdentityService.replenishOneTimePreKeys` and `DeviceRevocationService.revoke`

— which cannot be done without editing `lib/core/crypto/identity_service.dart` and
`lib/core/services/device_revocation_service.dart`, **neither of which is in the
fence**. (`identity_service.dart` appears in `required_context:`, which grants read
access, not write.)

Commit `23b23fb` (`feat(E11-T06)`) duly modified both:

```
$ git log --oneline development..HEAD -- lib/core/crypto/identity_service.dart
23b23fb feat(E11-T06): public device directory ...

$ git log --oneline development..HEAD -- lib/core/services/device_revocation_service.dart
23b23fb feat(E11-T06): public device directory ...
59e4724 feat(E11-T04): device revocation records and own-account propagation
```

`E11-T06` has **no §Deviations section at all** (`grep -n "^## " E11-T06.md` shows
§1–§9, §Open Questions, §Feedback log, §Run log — no §Deviations), so the
out-of-fence edits were never disclosed.

This is a **rule 6** violation on the builder's side and a task-authoring defect on
the planner's side, and the planner half is the real cause: given a task file whose
§3 and `files:` disagree, the builder had to break one of them. The edits
themselves are small, correct, well-commented, and exactly what §3 asked for — the
problem is that the contract did not authorise them and nothing recorded that.

Filed as a bug rather than waved through because the fence is what makes the
"only the task's files changed" review check meaningful; a fence that is routinely
exceeded without a §Deviations entry stops being evidence of anything.

## Repro
1. Read `epics/E11-firebase-sync/tasks/E11-T06.md` frontmatter `files:` — six paths,
   `delete: []`.
2. Read the same file's §3 — mandates wiring into two files not among those six.
3. `git log --oneline development..HEAD -- lib/core/crypto/identity_service.dart`
   → attributed to T06's own commit.
4. `grep -n "^## Deviations" epics/E11-firebase-sync/tasks/E11-T06.md` → no match.

## Expected
**Rule 6** — "`files:` … are binding. Never … refactor outside scope … Deviation =
stop, log to `## Open Questions`, request review." Either the fence lists every file
§3 requires, or the builder stops and logs the contradiction before editing.

## Actual
Two production files edited outside the declared fence, with no §Deviations entry
and no §Open Questions note about the contradiction.

## Severity
**S4** — process/traceability, not behaviour. The code changes are correct and
reviewed; nothing is functionally wrong *because of this finding alone*. Recorded
because it is the mechanism by which `E11-B01` stayed invisible: the wiring was
half-delivered into files nobody's fence claimed, so no reviewer was looking at a
contract that covered them.

## Fix direction
Retroactive, documentation-only — do **not** revert the code:
1. Add `lib/core/crypto/identity_service.dart` and
   `lib/core/services/device_revocation_service.dart` to `E11-T06`'s `files.update:`.
2. Add a `## Deviations` section to `E11-T06` recording the out-of-fence edits, the
   §3/`files:` contradiction that forced them, and the reason they were correct.
3. Fold the authoring lesson into the E11 retro: at sharding, cross-check every §3
   deliverable verb ("wires X into Y") against the `files:` fence, since a task that
   names a file only in `required_context:` cannot legally edit it. This is the
   check that would have caught it before dispatch.

## Regression test (write it first)
Not unit-testable — this is a task-file property. The mechanical equivalent is a
`make health` check: for each `done` task, assert the set of files its commits
touched is a subset of its `files:` fence, and flag any task with out-of-fence
paths and no `## Deviations` section. Worth proposing at the retro as an H-check
rather than building here.

## What this fix does NOT do
- Does **not** revert or alter any line of `identity_service.dart` or
  `device_revocation_service.dart` — the code is correct and separately reviewed.
- Does **not** re-open `E11-T06`'s review outcome or change its `status: done`.
- Does **not** fix `E11-B01` (the wiring is still not completed at the composition
  root) or `E11-B02` — this bug is only about the contract record.
- Does **not** change any other task's `files:` fence, or introduce a fence-checking
  hook (that is a retro proposal, not this fix).
