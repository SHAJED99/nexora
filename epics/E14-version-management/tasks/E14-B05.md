# E14-B05 · The route table doc does not list the route E14-T04 added

## The defect

`lib/app/routes.dart:2-3` says:

> See docs/routes.md for the full table including the routes not yet wired
> (owned by their feature epics).

`E14-T04` added `Routes.versionUpdateRequired = '/version-update-required'`
(`routes.dart:49`) and its `GetPage` entry (`routes.dart:117-121`), but
`docs/routes.md`'s wired-routes table ends at `/chat/:id` (line 31). The new
route appears nowhere in it. `docs/traceability.md` likewise has no entry.

A reader following `routes.dart`'s own pointer gets an out-of-date answer,
and the doc that is meant to be the index of every route silently is not.

## Repro

```
grep -n "version-update-required" docs/routes.md docs/traceability.md
```
→ no matches.

## Expected

`docs/routes.md`'s wired table carries one row per route registered in
`appPages`, per that file's own stated purpose.

## Actual

The table is missing `/version-update-required`.

## Severity

**S4** — documentation drift only. No runtime behaviour is affected. Filed
rather than fixed inline by the sweep because it is a table row plus a design
contract reference, not a one-line typo, and the reviewer does not edit
product artifacts.

## Suggested fix shape (not binding)

One row in the wired table:

```
| `/version-update-required` | `version-update-required` | `design/screens/version-update-required.md` | `lib/features/version/` (E14-T04) |
```

None meaningful for a doc row. Verification is the `grep` above returning the
