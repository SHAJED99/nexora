## 1. Goal
Let the user choose how this device manages its own storage, and see what the
active policy decided and why.

## 2. Business logic

Implements `FR-STORE-004` (mode selection), `FR-STORE-005` (the factors),
`FR-STORE-007` (the explanations) and — by **absence** — `FR-STORE-006`,
against `design/screens/settings-storage.md`.

**`FR-STORE-004` is half-owned and that is deliberate.** `E08-T05` owns the
persistence and the policy semantics (`StorageSettingsRepository`: `read`,
`watch`, `setMode`, `setBudgetBytes`, and the `minMaxBytes` conversion point);
**this task owns only the selection UI.** E08's Analyze report named that
half-ownership explicitly so it would be visible rather than assumed.

**Changing a mode changes what the *next* plan says. It runs nothing, applies
nothing and deletes nothing.** `E08-T06` owns execution alone. This is written
into the contract (`settings-storage.md`, §"The prohibition this screen exists
to keep") as well as here.

**The default screen must not imply an imminent deletion.** `OQ-E08-3` was
answered by the human on 2026-09-02 as option (a): Smart Mode's allow-list
excludes conversation content entirely, and message content is removed **only**
under a manual policy the user explicitly turns on. Smart Mode is the default,
so on a default install nothing this screen describes will delete a message.
SS12 and SS13 exist because of that answer; the copy is future-tense
(`Will remove:`), and there is no countdown, no "X days left", no badge and no
urgency colour.

## 3. What this task does
- Builds `StorageSettingsController` bound to
  `StorageSettingsRepository.watch()` and reading
  `StorageDecisionLog.latestPass()` plus the usage summary from
  `StorageInventory`.
- Builds `StorageSettingsView` composing `E15-T03`'s scaffold and rendering the
  contract's elements: the usage summary, the three-mode selector with the
  active mode marked, the active mode's parameter field (only when the active
  mode has one), and the explanation list for the latest plan.
- Adds its own probe test, verifies, and commits the first clean dump as the
  golden.

## 4. What this task does NOT do  ← the scope fence
- **Does NOT add a `Clean Now` button.** No apply-now, no confirmation dialog,
  no "free up space", no delete affordance — **not even a disabled one**.
  `FR-STORE-006` says in as many words that the user does not need to press
  one, `EARS-STORE-22` makes it a criterion, and `settings-storage.md` writes
  the prohibition into the contract because every storage screen anyone has
  ever seen has such a button.
- **Does NOT execute, schedule or trigger a retention pass.** `E08-T06` owns
  execution. Changing a mode writes a setting; it does not run anything.
- **Does NOT re-implement or second-guess the eight-factor scoring.**
  `E08-T04`'s `RetentionPlan` is the source of truth for what the screen says.
  If a widget and the plan disagree, the plan wins and the widget is the bug.
- **Does NOT add an export control.** `GAP-027` was resolved by the human as
  (c): no export, and the hub row's `Local cache, message retention, export`
  subtitle stays a **disclosed copy artifact**. Do not build one, and do not
  "fix" the hub row's copy — that would red the already-green `settings` gate.
- **Does NOT invent a storage-percentage denominator.** `GAP-026` recorded the
  `OQ-E08-1` decision; `budget_bytes` stays as `E08-T05` defines it. If the
  denominator is null, show what the contract says for that case.
- **Does NOT add a text input styled as an input.** No dark-surface text
  primitive exists in this design; SS17 is the parent's own card surface with a
  `JetBrains Mono` numeral (`settings-storage.md` §Derivation boundary 4).
- **Does NOT use red for validation.** `settings.md` measures no red;
  `devices.md`'s `rgb(186, 26, 26)` is destructive/blocked semantics. Use
  `error_outline` at a muted parent colour — GAP-009's approved precedent
  (§Derivation boundary 5).
- **Does NOT change `StorageSettingsRepository`, `RetentionPlan`,
  `StorageDecisionLog`, `StorageInventory` or any Drift table.**
- **Does NOT touch `lib/app/routes.dart`, `settings_controller.dart`,
  `settings_binding.dart` or `test/design/design_probe_test.dart`** — all four
  are `E15-T11`'s alone, and this is E08's own recorded warning.
- **Does NOT own `FR-STORE-002`/`FR-STORE-003`.** They are unowned
  (`OQ-E08-5`) and stay unowned; this task does not quietly absorb them.

## 6. Risks
- **The `Clean Now` reflex.** It is the single most likely defect in this task
  and it will look like an improvement. §4 and the contract both forbid it.
- **`categoryKey`/`reasonCode` are machine keys.** Rendering them raw is a copy
  failure the design gate will catch, but mapping them in the *repository* is a
  layering failure it will not — the mapping belongs in this screen.
- **The parameter field only exists for the mode that has one.** `olderThanDays`
  and `maxBytes` are both nullable and mutually exclusive; rendering both, or
  rendering one for Smart Mode, is a contract violation.
- **MiB vs MB.** `StorageSettingsRepository` fixes 1 MiB = 1,048,576 bytes as
  the one conversion point and says any further MB-facing display conversion is
  this screen's concern. **Convert once, here, and state it in a comment** —
  converting twice is the failure that file's own header warns about.
- **`E08-B01` (S1) is only reachable once this screen exists.** Its tracker row
  says "no — no UI can set a manual mode until `E08-T09`". Setting
  `overSizeMb` from this screen makes that path live. Confirm `E08-B01` is
  closed on `development` before this merges; if it is not, that is a finding
  for the sweep, not something to route around.
