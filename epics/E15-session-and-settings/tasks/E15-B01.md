# E15-B01 · `Get.lazyPut` without `fenix: true` crashes on a second welcome/login/home visit

## The defect
`AppBinding.dependencies()` is the app's `initialBinding` (`lib/app/main.dart:241`) — it
runs exactly ONCE per process, unlike a per-page `Bindings` (`ChatBinding`,
`DashboardBinding`, etc., wired via `GetPage.binding:` in `lib/app/routes.dart`),
which re-registers on every route visit. `WelcomeController`, `LoginController`
and `HomeController` were registered via `Get.lazyPut(...)` with no
`fenix: true` (`lib/app/bindings.dart:130-134`, pre-fix). GetX's smart
management disposes a controller once its route is popped, and a plain
`lazyPut`'s factory is consumed the first time the controller is deleted — so
any SECOND visit to `/welcome`, `/login` or `/home` within the same process
throws `"X" not found`.

## Repro
Physically hit live: relaunch the app after backgrounding (or after any full
navigation back to `/welcome`), tap "Continue with Google" a second time in
the same process:
```
"LoginController" not found. You need to call "Get.put(LoginController())" or
"Get.lazyPut(()=>LoginController())"
```
`WelcomeController` and `HomeController` share the exact same exposure —
confirmed by the regression tests below, each independently.

## Expected
A route with no per-page `Bindings` of its own, registered only through the
app's one-time `initialBinding`, must still be revisitable any number of
times in the same process — GetX's own `fenix: true` flag exists precisely
for this shape.

## Actual
Hard crash on the second visit. This would have also broken the just-planned
E15 logout feature outright (logout routes back to `/welcome`, then the user
signs in again — the exact repro shape).

## Severity
**S1.** A reachable, deterministic hard crash on completely ordinary use
(backgrounding and returning), not an edge case.

## Fix (implemented)
Added `fenix: true` to all three `Get.lazyPut` calls in
`AppBinding.dependencies()`. `fenix: true` keeps the lazy factory alive for
the process's lifetime, letting GetX recreate the controller on demand every
time it's needed again after disposal — the standard fix for this exact GetX
failure mode.

## What this fix does NOT do
- Does **NOT** touch any of the `Get.put(..., permanent: true)` singletons in
  the same file — those are never disposed by smart management and have no
  version of this exposure.
- Does **NOT** touch any per-page `Bindings` (`ChatBinding`, `DashboardBinding`,
  `DevicesBinding`, `SettingsBinding`, `ConversationsBinding`,
  `_VersionUpdateBinding`) — confirmed structurally immune, since each
  re-registers its own `lazyPut` on every route visit.
- Does **NOT** add a new controller-lifecycle abstraction or change how
  `AppBinding` itself is wired into `main.dart`.
