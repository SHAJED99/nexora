# E13-B03 · `ObservabilityService.instance` cannot be safely exercised for real inside a widget test

## The defect

`ObservabilityService.instance` (`lib/core/observability/observability_service.dart:145`)
is a `static final` singleton, constructed once with the real
`SentryObservabilityClient()` as its default client:

```dart
ObservabilityService._({ObservabilityClient? client})
    : _client = client ?? SentryObservabilityClient();

static final ObservabilityService instance = ObservabilityService._();
```

The only test-facing seam, `ObservabilityService.withClient(fakeClient)`
(used correctly by `observability_service_test.dart`), constructs a
**separate** instance — it cannot substitute the client backing the shared
`.instance` singleton. Any production call site (like `LoginController`,
which calls `ObservabilityService.instance.logError(...)` directly, with
no injected `ObservabilityService`/`ObservabilityClient` parameter) can
therefore only be observed in a test by exercising the REAL client.

## Repro (confirmed)

An isolated probe — a single `testWidgets` calling only
`await ObservabilityService.instance.init().timeout(Duration(seconds: 5), onTimeout: () => print('TIMED OUT'))` —
never printed "TIMED OUT" and never completed even after several minutes
inside a plain `flutter test` run (no `--platform chrome`, no real device).
Since this is a `.timeout()`-wrapped `Future`, an ordinary slow-but-
eventually-completing async operation would still have fired the timeout
callback; the fact that it did not strongly suggests a genuinely blocking,
non-cancellable native/network call inside `SentryFlutter.init()` — likely
attempting to bootstrap the native Sentry platform-channel integration
with no real engine/platform binding present to answer it.

## Expected

A test should be able to exercise `ObservabilityService.instance`'s real
call sites (production code that hardcodes `.instance`, not an injected
client) without risking an indefinite hang, OR there should be a
documented, safe way to do so.

## Actual

Calling `ObservabilityService.instance.init()` for real, inside a `flutter
test` VM environment, hangs indefinitely with no timeout, no error, no
diagnostic — the test run itself must be killed externally.

## Severity

**S3** — no production impact (this never manifests outside a test
process), but it silently removed real test coverage: `E12-B08`'s own
regression test had to have its log-content assertion removed at this
merge (see `login_controller_enrollment_gate_test.dart`'s own comment on
`test_EARS_AUTH_3_device_identity_read_failure_falls_through_to_dashboard`)
because there was no other safe way to verify it. Any FUTURE test wanting
to verify a log message from a production call site hardcoding
`ObservabilityService.instance` will hit the same wall.

## Suggested direction (not binding, builder's call at dispatch)

- Give `ObservabilityService` a way to substitute the client backing the
  shared `.instance` singleton in tests (e.g. a `@visibleForTesting` setter,
  or restructure call sites to accept an injected `ObservabilityService`
  rather than hardcoding `.instance` — the latter is a larger refactor
  touching every call site, the former is a narrower, safer fix).
- Alternatively/additionally, investigate why `SentryFlutter.init()`
  specifically hangs rather than completing quickly or throwing when no
  DSN is configured and no platform binding exists — if there's a
  legitimate fix inside `SentryObservabilityClient.init()` itself (e.g.
  skipping native bootstrap entirely when the DSN is empty, rather than
  attempting it and hanging), that closes the root cause rather than only
  working around it in tests.

## What this fix does NOT do
- Does NOT restore the specific log-content assertions removed from
  `login_controller_enrollment_gate_test.dart` — that's a natural follow-up
  once a safe seam exists, not part of this task itself.
- Does NOT change any of `SentryObservabilityClient`'s privacy-conscious
  configuration (`ADR-0006`, `E13-T06`) — this is a testability fix, not a
  behavior change.
