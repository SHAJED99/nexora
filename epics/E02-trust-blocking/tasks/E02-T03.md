# E02-T03 · Settings screen — top-level menu

## 1. Goal
Build the real `/settings` screen as a navigation hub, exactly as designed
— eight rows (Account, Privacy & Security, Security Center, Network,
Storage, Battery, Notifications, About).

## 2. Business logic
This screen is a menu, not a settings-editing surface — none of its rows
have a designed sub-screen yet. FR-TRUST-006 (auto-accept rules,
block-list management, location-access toggle) would live under "Privacy
& Security", but no design contract exists for that sub-screen. Per rule
2, this task builds only what the contract shows and logs the missing
sub-screen as a gap rather than inventing one.

## 3. What this task does
- Real `/settings` route, screen, controller, binding — the eight menu
  rows exactly as `design/screens/settings.md` specifies (icons, labels,
  descriptions, chevron affordance).
- Each row is tappable; since no sub-screens are designed/built yet,
  tapping any row shows a lightweight "Coming soon" acknowledgement
  (e.g. a `SnackBar`) rather than a dead tap or a fabricated screen.
- Adds one `design/gaps.md` entry: the "Privacy & Security" sub-screen
  needed for FR-TRUST-006's actual controls (auto-accept-trusted,
  auto-accept-specific, require-auth-for-unknown, block-list view,
  location-access toggle) doesn't exist in the design source — traced to
  FR-TRUST-006, status 🟡 proposed, needs 🧍 human approval before any
  future task builds it.

## 4. What this task does NOT do
- Does NOT build any sub-screen (Account, Privacy & Security, etc.) — none
  are designed yet.
- Does NOT implement any of FR-TRUST-006's actual toggles/config
  persistence — that's blocked on the gap above being resolved.
- Does NOT touch the Devices screen (E02-T02).
