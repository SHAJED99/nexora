# E12-B05 · the `devices` screen has not actually been gated

## The defect

`test/design/design_probe_test.dart`'s `devices` fixture registers two of the
three dependencies `DevicesBinding` needs:

```dart
// test/design/design_probe_test.dart:124-126
Get.put<RelationshipRepository>(repository, permanent: true);
Get.put<BlockUseCase>(BlockUseCase(repository), permanent: true);
DevicesBinding().dependencies();
```

`TransportService` is never registered, so the dumper's own
`DevicesController` construction throws and the probe honestly records
`{"renderError": true, "elements": []}`.

Every `make design-verify SCREEN=devices` run since this gap opened has
reported **0% (0/61)** — not a real regression, and not a real gate either.
A screen that scores 0 on a render error looks identical to a screen that
was gutted, which is exactly the failure mode the design-fidelity gate
exists to prevent.

Confirmed by T02's cross-model reviewer via byte-for-byte reproduction
against both `epic_12` and the unmodified `origin/epic_12` baseline —
identical output on both, so no E12 task caused it and none could fix it
from inside its own fence.

## Repro

1. `make design-verify SCREEN=devices`
2. Read `design/reports/devices/…/report.md` → 0/61, `renderError: true`.

## Expected

The `devices` probe renders the real screen and the gate reports a genuine
match percentage against `design/screens/devices.md`.

## Actual

`renderError: true`, `elements: []`, 0%.

## Severity

**S3** — the screen itself is fine; the gate measuring it is blind. Workaround
is manual inspection, which `skills/design-fidelity` exists specifically to
reject ("a build with five real defects sat at 0.04% pixel difference").

## Fix

One line in the `devices` `setUp`, mirroring what
`devices_controller_test.dart` already does for its own harness: register a
`TransportService` (mocked native side) before `DevicesBinding().dependencies()`.
Then re-run the gate and record the real baseline number.

## What this fix does NOT do

- Does **not** change `devices_view.dart`, `devices_controller.dart`, or
  `DevicesBinding` — the production screen is not the defect.
- Does **not** hand-edit `design/screens/devices.md` or any generated table
  (design-fidelity rule 1).
- Does **not** relax `thresholds.yaml` to make the resulting number pass
  (rule 2 — that is the `design_threshold_relaxation` human gate). If the
  honest score after this fix is red, that is a separate finding to file.
- Does **not** register any other screen's probe fixture (see `E12-B06`).
