# E12-B06 · derived screens are contracted but never gated

## The defect

`design/sources.yaml` registers **7 screens, all `source: ui`**. None of the
`source: derived` contracts written and built across E06-E11 are registered —
including E12's own two, from the approved `GAP-028`:

- `design/screens/device-enrollment.md`
- `design/screens/device-enrollment-approval.md`

So `make design-verify SCREEN=device-enrollment` fails with "no screen
matched" rather than gating anything. `skills/design-fidelity` §3 is explicit
that this should not be true:

> Derived screens get a contract too — hand-written, marked `source: derived`.
> Once built, extract the built screen as its own golden so it is regression-
> gated from then on like everything else.

The second half of that sentence has never been executed for any derived
screen.

## Consequence for E12 specifically

E12 shipped **two** UI tasks, both carrying `design_contract:` frontmatter,
and **neither could ever run its own gate**. Both were hand-verified instead
(codepoint-exact copy match, token-by-token style match, confirmed by an
independent reviewer pass) — real verification, but ungated and
non-regression-protected. Any future change to these two screens is
unprotected.

This also blocks resolving tracker item **C3** (`DeviceEnrollmentView`'s
primary button rendering 342px against the contract's measured 326px): that
discrepancy cannot be adjudicated until `device-enrollment` has a golden of
its own to measure against.

## Repro

1. `make design-verify SCREEN=device-enrollment` → "no screen matched".
2. `grep 'source: derived' design/sources.yaml` → no matches.

## Expected

Every built screen with a contract is registered and gated, derived or not.

## Severity

**S3** — the screens are believed correct and were manually verified; what is
missing is the machine gate and its regression protection. No user-visible
defect follows directly from this today.

## Note — this is also a sharding defect worth a retro lesson

`E12-T03`'s own contract implied that extraction happens as part of the build
task. It does not: registering a derived screen in `design/sources.yaml` plus
adding a `test/design/design_probe_test.dart` probe block is planner-owned
(`design-fidelity` §1 Ingest). A builder task that carries a
`design_contract:` it structurally cannot verify is a task that cannot meet
its own DoD. Route to `skills/retro`.

## What this fix does NOT do

- Does **not** change any built screen's widget code to improve its score.
  If registering a screen reveals a red gate, that is a **new finding to file**,
  not a licence to reshape the widget tree (design-fidelity rule 5,
  `L-frontend-001`).
- Does **not** relax `thresholds.yaml` (rule 2 — human gate).
- Does **not** hand-edit any generated contract table (rule 1).
- Does **not** fix the `devices` probe fixture (`E12-B05`, separate).
