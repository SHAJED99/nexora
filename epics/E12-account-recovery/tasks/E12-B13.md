# E12-B13 · the design-verify probe under-measures every screen it dumps, not just `devices`

## The defect

`test/design/flutter_probe_dumper.dart` (shared by every screen's design-verify
run, not E12-specific) has at least seven confirmed blind spots:

1. **No `heading` role is ever emitted.** Only `'button'`, `'generic'`,
   `'textbox:*'` role strings exist in the dumper — a golden with 6
   `heading:N` elements can never match them, regardless of implementation.
2. **Elements nested inside an interactive ancestor are swallowed.**
   `_walk`'s `insideInteractive: true` recursion means `Text`/`Icon` widgets
   inside `InkWell`/`IconButton`/`OnProcessButtonWidget` never get dumped —
   including **the interactive element's own label**, confirmed: every
   `button`-role element in a real dump has `text: ""`.
3. **`button`-role elements never capture color/fontSize/fontFamily.** Only
   `background`/`radius`/`borderWidth`/`borderColor` are read for buttons;
   `OnProcessButtonWidget.borderRadius` specifically is never read either.
4. **`Icon` widgets never carry font metadata** — every icon glyph produces
   an unwinnable `fontSize`/`fontFamily` delta pair against the golden's
   measured values (Material Symbols Outlined, 24px).
5. **8-bit alpha rounding** can't represent an exact literal opacity like
   `0.1` (`0x1A/255 = 0.10196..., rounds to 0.102` — a permanent Δ1 finding).
6. **DOM-only wrapper elements** (`<nav>`, `<a>`, `<header>`) have no Flutter
   equivalent and can never match, inflating "missing element" counts.
7. **Only the TOP border is read** (`_decorationOf` reads `border.top`
   specifically) — a design source using `border-b`/`border-t` on the
   opposite edge from what the probe checks is invisible to the gate on
   both the golden and implementation side equally, so a real, correct fix
   can show as unmeasured rather than passing.

## Why this matters beyond one screen

`E12-B12` (the `devices` screen's own design-fidelity bug) found that of its
23 "missing element" findings, roughly all of them trace to causes 1, 2, or 6
above — not to real `devices_view.dart` defects. A screen could be pixel-
perfect and still fail this gate by a similar margin. Since this dumper is
shared project-wide, **every screen's design-verify score is under-measuring
real fidelity**, in a way that's currently invisible unless someone manually
traces each finding to its root cause (as `E12-B12`'s reviewer did).

## Severity

**S3** — the gate still catches real defects (it is not useless), but its
false-positive rate on "missing"/"style" findings means a red score cannot
be trusted at face value without manual triage, which defeats the purpose
of an automated gate (`skills/design-fidelity`'s whole premise).

## Suggested direction (not binding, builder-ui's call at dispatch)

- Add a `heading` role heuristic (e.g. `Text` with a known heading-scale
  `TextStyle` inside a recognizable header context).
- Fix the interactive-ancestor swallowing to still emit the nested
  text/icon's own properties, tagged as belonging to the interactive parent
  rather than dropped.
- Capture color/fontSize/fontFamily for `button`-role elements and read
  `OnProcessButtonWidget.borderRadius`.
- Add font metadata capture for `Icon` widgets.
- Read both `border.top` and `border.bottom` (report whichever is non-null,
  or both) rather than only `border.top`.
- DOM-only wrapper elements and 8-bit alpha rounding may be acceptable,
  documented exclusions rather than things to "fix" — use judgment.

## What this fix does NOT do
- Does NOT change any screen's actual implementation to work around these
  limitations — this is a probe/tooling fix, and changing UI to game a
  flawed measurement is the `L-frontend-001`/design-fidelity-rule-5 mistake
  this bug exists to prevent happening again.
- Does NOT relax `thresholds.yaml` — that's a separate, unrelated human gate.
- Does NOT re-run every screen's design-verify and re-triage every score —
  that's a natural follow-up once the dumper itself is fixed, not part of
  this task.
