# E07-B03 · The make-before-break controller is built, tested, and never run

## The defect

```
$ grep -rn "CallMigrationController(" lib/
lib/core/calls/call_migration_controller.dart:88:  CallMigrationController({
```

Only its own declaration. Every other E07 collaborator **is** composed in the
root — `MessagingStack` builds `CallSignaling` at `messaging_stack.dart:368`
and `SendGroupMessageUseCase` at `:353` (the latter is exactly what
`E07-T14` was created to fix for the group vertical). The migration
controller is the one piece with no call site, so FR-CALL-003's entire
make-before-break sequence executes only in `call_migration_controller_test.dart`.

**This is not a straight copy of `E07-T14`'s fix.** `SendGroupMessageUseCase`
is a single long-lived collaborator; `CallMigrationController` is
**per-call** — "constructed once per call attempt, [start]ed when the session
reaches `CallState.active`, [stop]ped on `ending`/`ended`"
(`call_migration_controller.dart:83-86`). The wiring point is therefore
inside `CallSignaling`'s own session lifecycle, not a new `MessagingStack`
field.

## Repro
1. `grep -rn "CallMigrationController(" lib/` — one hit, the declaration.
2. Trace any path from `MessagingStack.create` to `evaluateOnce` — none exists.
3. Place a call end-to-end: the session reaches `active`, and no migration
   timer is ever started, so no candidate route is ever considered.

## Expected
FR-CALL-003 — an active call migrates to a better route make-before-break.
Reachable in the shipped app, not only from a test.

## Actual
Unreachable. The behaviour is fully built and proven by tests that construct
the controller directly.

## Severity
**S3.** Defensible while the media half is deferred — with
`NullCallMediaTransport` every migration correctly stops at the media-attach
step and stays on the old route, so wiring it *today* would add a 1s-tick
timer per call that always fails at step 6. But a shipped requirement that
no code path can reach is a real gap, and it is exactly the shape
`skills/bug-sweep` exists to make explicit rather than leave implicit.

## Fix direction — fold into the prospective real-time media-path task
Do **not** fix this standalone. `E07-T11`'s review recorded three more seam
findings on the same code that must be resolved in the same pass, all
independently re-confirmed by this sweep against the source:

- **O1 (S3)** — `_awaitMediaLive` subscribes to `media.health` *after*
  `await media.attach(session)` (`call_migration_controller.dart:261` then
  `:270`). A real transport emitting `live` synchronously during `attach` on
  a broadcast stream loses the event and the migration times out forever.
  Fix is small: subscribe before `attach`. **Confirmed accurate.**
- **O2 (S3)** — the seam carries no route identity:
  `attach(CallSession)` / `detach()` (`call_signaling.dart:361,363`), and
  `session.recordActiveRoute(candidate)` only runs at step 8 *after*
  `detach()`, so `session.activeRoute` still holds the OLD route at attach
  time. A real transport cannot learn which route to bring up, and an
  argument-less `detach()` is indistinguishable from "tear down everything".
  **Confirmed accurate — this seam must be reshaped, which is also the right
  moment to fix `E07-B02`.**
- **O3 (S4)** — a `stop()` landing between `setActiveRoute(candidate)` and
  media confirmation returns at `:262`/`:271` **without** the
  `setActiveRoute(oldRoute)` compensation the other failure paths perform,
  so `RoutingEngine` keeps `candidate` as active. Inert (the candidate is
  probe-validated by then, and `stop()` only fires on call end), but
  inconsistent with §3's "leave the active route exactly as it was".
  **Confirmed accurate.**

`OQ-E07-3` was resolved on 2026-08-31 (tracker §Gates), so that task is no
longer blocked — note the tracker's §Blocked/Frozen section still says
otherwise and needs reconciling.

## What this fix does NOT do
- Does **NOT** choose or implement a media transport — that is the
  media-path task's own scope, gated by `OQ-E07-3`'s resolution, not this
  entry's.
- Does **NOT** add a second migration heuristic, hysteresis, or a
  "force migrate" API — `RoutingEngine` owns the decision
  (`E07-T11` §4), and this fix stays a caller.
- Does **NOT** change `RoutingEngine.considerMigration`'s improvement ratio
  or stability window.
- Does **NOT** make a media-attach failure end an active call — EARS-CALL-10
  forbids it, and `E07-T11` deliberately relocated that side effect.
- Does **NOT** touch `CallSession`'s state machine or `call_signaling.dart`'s
  invite/accept paths beyond the lifecycle hook the wiring needs.

## Fix (implemented)

`CallSignaling._track` now constructs a `CallMigrationController` and
calls `start(session)` the instant a session reaches `CallState.active`
— BEFORE `_attachInitialMedia`, so `start()`'s own route-seeding
(`RoutingEngine.setActiveRoute`/`CallSession.recordActiveRoute`) has
already populated `session.activeRoute` by the time the initial attach
reads it. Tracked in a new `_activeMigrations` map keyed by `callId`,
removed (and `stop()`ped, harmless if `CallMigrationController.stop()`
already ran via its own `CallState.ending`/`ended` listener) on
`CallState.ended`.

**O1** — `evaluateOnce()`'s health-live subscription is now set up
BEFORE `media.attach()` is called, not after. A real transport reporting
`live` synchronously during `attach` (entirely plausible) used to be
silently missed by a broadcast stream with no listener yet.

**O2** — `CallMediaTransport.attach`/`detach` now take an explicit
`Route?` parameter, threading the candidate/old route through directly
rather than letting a caller infer it from `CallSession.activeRoute`
(which still holds the OLD route at the moment `attach` is called for
the migration candidate, by design — `recordActiveRoute` only runs after
the new route is proven live). `NullCallMediaTransport` and
`CallSignaling._attachInitialMedia` updated to match; the initial attach
passes `session.activeRoute` (now populated by the migration controller's
own `start()`, seeded before the initial attach ever runs).

**O3** — both `_superseded(myGeneration)` early-returns AFTER
`setActiveRoute(candidate)` (step 5) now restore `oldRoute`, matching the
sibling `attachFailure`/`!live` branches that already did.
