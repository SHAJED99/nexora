# E07-T13 · PTT, resolved

> **This task exists so that push-to-talk has a named owner.** It is the
> discharge of `OQ-E07-2`, `GAP-017` and `IMP-001` — the human's 2026-08-30
> decision to park PTT until E07's voice-call work settles the real-time
> transport question, and to re-home the FR-COMM-001/002 PTT obligation to
> this epic. `IMP-001` §Effort/risk names the exact failure this task
> prevents: *"if E07's sharding pass doesn't read `OQ-E07-2`, the
> obligation could be dropped a second time — the same failure shape
> `E05-B02` already demonstrated once."* It is now a task, not a note.

## 1. Goal
Answer the three questions GAP-017 says must be answered before PTT can
have a design at all, and turn the answers into either a derived contract
(`design/screens/chat-ptt.md`) or an explicitly-recorded decision not to
ship PTT in v1 — never a third silent deferral.

## 2. Business logic
- **`GAP-017`'s three open questions are this task's actual scope:**
  1. Is PTT a live half-duplex stream (a transport problem, shared with
     voice calls), or a fast voice-message loop layered on `GAP-014`'s
     already-approved recording UI?
  2. Does a PTT transmission leave a message in the thread afterwards, or
     is it ephemeral?
  3. Is it per-conversation, or its own surface?
- **Question 1 cannot be answered before `OQ-E07-3` is.** That is the
  entire reason the human parked PTT. If the real-time media transport
  chosen for calls turns out to be a datagram path over the existing mesh,
  PTT is close to free — it is the same path with a
  hold-to-transmit gate and no duplex mixing. If it turns out to be
  WebRTC or a connection-oriented native channel, PTT is a materially
  different and more expensive proposition, and the honest answer may be
  "layer it on `GAP-014`'s voice messages for v1" or "not in v1".
  **This task must not be started while `OQ-E07-3` is open**; its
  `depends_on` is `E07-T12` for the contract style, but its *real*
  precondition is that human answer, and starting early would re-open a
  question the human already closed.
- **The output is one of three, all acceptable, none silent:**
  (a) a derived contract `design/screens/chat-ptt.md` plus a GAP entry
  superseding GAP-017; (b) a recorded decision that PTT layers on
  `GAP-014` with a small delta contract; (c) a recorded decision that PTT
  is not in v1, with the FR-COMM-001/002 clause explicitly re-homed to a
  named future epic via `skills/change-impact` — the same route `IMP-001`
  itself took. **What is not acceptable is a fourth "revisit later" with no
  owner.**
- **Rule 2 still binds.** If (a), every element derives from an existing
  primitive — `chat.md`'s composer, `chat-voice.md`'s recording treatment,
  `dashboard.md`'s status card for a transmitting/listening indicator — and
  the `approved by:` line ships bare for the human.
- **PTT is named for groups too** (`FR-COMM-002`), and a half-duplex
  channel in a group is a floor-control problem (who is transmitting, what
  happens on collision) that a 1:1 answer does not cover. Whatever this
  task decides must say something explicit about the group case, even if
  that something is "1:1 only in v1, group PTT re-homed".

## 3. What this task does
- Reads `OQ-E07-3`'s answer and `E07-T09`/`E07-T11`'s actual media seam,
  then answers GAP-017's three questions in writing, with the reasoning.
- Produces one of the three §2 outcomes, in `design/gaps.md` as a new
  entry (GAP-0xx) that **supersedes GAP-017 by reference rather than
  editing it** — GAP-017 records a decision the human made and stays as
  written.
- Updates `epics/E07-groups-calls/epic.md`: `OQ-E07-2`'s status moves from
  🟡 to 🟢 with the answer recorded verbatim, and §Tasks gains either a
  prospective PTT build task or an explicit re-home line.
- If outcome (c): writes the `docs/impact/IMP-002` report re-homing the
  FR-COMM-001/002 PTT clause, because dropping scope is a change-impact
  class (`dropped scope`) and rule 3 reserves it to the human.

## 4. What this task does NOT do
- Does **NOT** implement PTT, add a plugin, or touch any Dart file.
- Does **NOT** answer `OQ-E07-3` on the human's behalf, and does **NOT**
  proceed while it is open.
- Does **NOT** edit `GAP-017` or `IMP-001` — both record decisions already
  made; new information supersedes by reference (`skills/change-impact`:
  history edited teaches nothing).
- Does **NOT** self-approve any contract it writes (`L-process-002`).
- Does **NOT** silently narrow FR-COMM-001/002's PTT clause. Narrowing it
  is outcome (c) and requires an IMP report and the human.

## 5. Contract

### External services & flags

## 6. Risks
- The pressure at this point in the epic will be to produce *something*
  quickly. Outcome (c) — "not in v1, re-homed with an IMP report" — is a
  perfectly good result and is far better than a contract nobody can
  build. `E06-T13` earned its keep precisely by refusing to draw one.
- Superseding-by-reference is easy to get wrong under time pressure; the
  tempting edit is to change GAP-017's `decided by:` line. Don't.
- The group floor-control case is the part most likely to be skipped
  because FR-COMM-002's mention of PTT is one word in a list. One word in
  the spec is still spec (rule 1).
