# E07-T16 · The create-group entry point

## 1. Goal
`/groups/new` was built and merged (`E07-T15`, #325) and fixed (`E07-B05`,
#332), and until now **no screen linked to it**. This task adds the one
affordance that makes the group journey startable by a user.

## 2. The decision this implements
`design/screens/group-create.md` §Open proposed the affordance and left it
undecided; `GAP-018`'s clearance explicitly did not cover it.

**Human decision, 2026-09-25 — approved as proposed:** a 48×48 `r9999px`
button in the `conversations.md` header carrying the existing `add` glyph at
`24px` `rgb(195, 192, 255)`, with the instruction to *"treat the resulting
measured-contract delta honestly; do not edit the contract merely to conceal
it."*

## 3. Contract
- `_Header` (elements 1-5) gains one trailing icon button, in the same
  `Material`/`InkWell`/`SizedBox(48,48)` shape the `search` action already
  uses. `Icons.add`, `size: 24`, `NexoraColors.welcomeHeading`
  (`rgb(195, 192, 255)`) — every value already in use on this screen.
- `ConversationsController.openCreateGroup()` navigates to
  `Routes.groupCreate`.
- Ordering: `search` then `add`, so the existing element indices 4-5 keep
  their positions and the new element is appended rather than inserted.

## 4. What this task does NOT do
- Does **NOT** hand-edit `conversations.md`'s measured element table to add
  the new element. It is a *measured* contract; `design-fidelity` rule 1 and
  `E07-T12` §4 both forbid that, and the human's decision says so explicitly.
  The resulting extra-element finding is expected and is traced to
  `group-create.md` §Open / `GAP-018`.
- Does **NOT** change any other element, colour, spacing or copy on
  `conversations.md`.
- Does **NOT** add a FAB or a row inside the `Groups` section — both were
  considered and rejected in `group-create.md` §Open.
- Does **NOT** touch the group thread (`GAP-020`) or group row tap behaviour
  (`E07-B01`).

## 5. Acceptance criteria (EARS)
- **EARS-GROUP-21**: WHEN the user taps the create-group affordance in the
  Conversations header, the system SHALL navigate to `/groups/new`.
  (`FR-GROUP-001`)

## 6. Test strategy
`E07-B05` shipped because every test asserted against an injected navigation
seam and nothing exercised the real destination. This task does not repeat
that:

- the tap test asserts `Get.currentRoute` is `Routes.groupCreate` after a
  real tap on a real widget, **and**
- asserts that `appPages` — the application's own route table — actually
  registers a page under that name. A route string that matches nothing is
  a silent no-op in GetX, which is exactly how an inert affordance would
  pass a weaker test.

## 7. Definition of Done
- [ ] The button renders in the header with the specified geometry and colour
- [ ] Tapping it reaches the real registered `/groups/new` route
- [ ] `flutter analyze` clean, relevant suites green
- [ ] `make design-verify SCREEN=conversations` run, and its delta reported
      honestly rather than hidden
- [ ] Independent review (rule 5)
