# E08-B06 · "Will remove:" describes the past on one of the card's two paths

## The defect

`StorageManager.runPass` publishes the plan **before** executing it, and
never clears or replaces it afterwards:

```dart
// lib/core/storage/storage_manager.dart:151
latestPlan.value = plan;
...
// :162  await executor.apply(plan, allowedKinds: allowedKinds, ...);
```

The dashboard prefers that in-memory plan:

```dart
// lib/features/dashboard/presentation/dashboard_controller.dart:383-386
final plan = _storage.latestPlan.value;
final decisions = plan != null
    ? _decisionsFromGroups(_actionableGroups(plan))
    : _decisionsFromLog(await _storage.log.latestPass());
```

`_actionableGroups` (`:497-506`) filters on relay-payload kind and
Smart-Mode-messages only. It has **no** equivalent of the log path's
outcome filter — while `_decisionsFromLog` (`:473`) does, with its own
doc comment stating the rule:

```dart
if (row.outcome == DecisionOutcome.applied.name) continue;
/// - `outcome: applied` means the items are already gone by the time this
///   reads — showing them as "Will remove" would describe the past as a
///   forecast, so they are excluded;
```

So in the same process as an applying manual pass, the card lists the items
that pass just deleted, under "Will remove:", and sets
`warningActive: true` for them. After a relaunch, the durable path renders
the same pass correctly as nothing to remove. The controller's own header
claims *"the view cannot tell which path fed it"* — here it can.

## Repro
1. Manual mode (`olderThanDays`) with real candidates.
2. `StorageManager.runPass(nowEpochMs: now)` (apply, the tick's default) —
   the items are deleted and logged `outcome: applied`.
3. In the **same** process, `DashboardController._loadStorageUsage()`.
4. Compare against the same read after constructing a fresh
   `StorageManager` over the same database (the relaunch path).

## Expected
FR-STORE-006/007 — the informational card describes what the policy *will*
remove. `design/screens/dashboard.md`'s "Will remove:" copy is a forecast.
Both rendering paths must agree, which is `E08-T08` §2's own stated
guarantee.

## Actual
Step 3 lists the deleted items and shows the warning as active; step 4
lists nothing. Same pass, same database, two different answers.

## Severity
**S4** — cosmetic and transient: it self-corrects on the next pass or
relaunch, no data is affected, and it cannot fire under Smart Mode (whose
allow-list is empty, so no group is ever `applied`). It needs a manual mode
that actually deleted something, which no shipped UI can enable today
(`E08-T09` is prospective). Recorded because the two paths' divergence is a
real, verifiable contradiction of a stated invariant, not because it hurts
anyone now.

## Fix direction
Either clear/replace `latestPlan` after `executor.apply` with a plan
reflecting what remains, or give `_actionableGroups` the same
already-applied exclusion the log path has — most simply by having
`_loadStorageUsage` prefer the durable log unconditionally, and treating
`latestPlan` as an optimisation rather than the primary source. The log
path is already the fully-reviewed one (T08 round 2 falsified all five of
its filters), so converging *onto* it is the lower-risk direction.

## Regression test (write it first)
One test that runs an applying manual pass and asserts the in-process card
read and the fresh-manager card read produce the same `storageExplanation`.
Must fail on today's code.

## Related, and deliberately NOT a defect
The T08 round-2 carried-forward observation about a
**skipped-for-other-reasons** row (e.g. the undelivered-message guard,
`retention_executor.dart:230`) rendering under "Will remove:" was
re-examined by this sweep and is **confirmed correct, not a bug** — those
items genuinely become removable once delivered, so a forecast is the right
description, and both paths agree on it. Do not "fix" it.

## What this fix does NOT do
- Does **not** change the five log-path filters, `_policySummaryKeyFor`, or
  any user-facing string (design copy is `E08-T07`'s, character-for-character).
- Does **not** add any action affordance to the card — `EARS-STORE-2` and
  the structural no-`InkWell`/no-button test stand.
- Does **not** reshape the widget tree or touch
  `test/design/flutter_probe_dumper.dart` (`L-frontend-001`,
  `OQ-E08-T08-2`).
- Does **not** touch `StorageManager`'s throttle semantics or the tick.
- Does **not** change the Network Status card.
