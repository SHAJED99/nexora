# E08-T08 · Dashboard Local Storage card, for real

## 1. Goal
Turn the dashboard's Local Storage card from `GAP-011`'s honest placeholder
into the real thing: measured figures, the informational warning
`FR-STORE-006` requires, and the expansion that explains what the active
policy decided and why (`FR-STORE-007`) — without ever asking the user to
press "Clean Now".

## 2. Business logic
- **`EARS-STORE-2` (epic) lives here.** The warning is informational. There
  is no "Clean Now" button, no confirmation prompt, no badge that demands
  action, and no path from this card that deletes anything. Tapping it
  expands an explanation; that is all it does.
- **`GAP-011` closes here.** Its approved resolution was: real on-disk
  figure if cheaply available, a disclosed placeholder otherwise, and
  `Smart Mode - Older than 10 days` as static copy "until E08 builds the
  retention policy it describes". E08 has now built it, so the line becomes
  the **real** active policy's summary — mode plus its actual parameter.
- **Never synthesize a measurement** — `dashboard_controller.dart`'s
  standing prohibition, inherited verbatim. `percentUsed` renders only when
  a real denominator exists (`storage_policy_settings.budget_bytes`,
  `OQ-E08-1`). Until then `isMeasured` stays `false` and the card shows the
  real measured **bytes** with the design's own typography, disclosing the
  deviation from the `45% used` string in §9 and in `GAP-026`. A fabricated
  percentage is not an option, and neither is inventing the denominator.
- **The card reads; it never triggers a pass.** `StorageManager.latestPlan`
  and `StorageDecisionLog.latestPass()` are observed. A screen that starts
  a retention pass in order to render is a screen that deletes data because
  someone opened the app.
- **Copy is character-for-character from the contract.** `Local Storage`,
  the usage line, the warning line and every expanded reason string come
  from `dashboard.md` and `E08-T07`'s derived expanded-state section — not
  from the BRD, not from the controller, not from a `switch` that phrases
  reasons in the developer's own words.
- **`L-design-002`, now a rule, is claimed here.** This task widens a
  design-contracted screen's displayed data shape, so the shared probe
  fixture (`test/design/design_probe_test.dart`) must seed a storage plan
  or the gate is structurally blind to this card's new content. **And
  because this is the next task in the project to touch that file**, E07's
  retro carry-forward — the fixture still seeds zero group conversations,
  re-disclosed by three separate readers across two tasks — is closed here
  too, narrowly: one group-conversation seed, nothing else.
- **Empty and pre-first-pass states are real states**, not spinners
  forever: before any pass has run there is no plan, and the card renders
  its measured usage with no warning row — the same "first stream emission
  pending" contract the file already establishes for `loading`.

## 3. What this task does
- Widens `StorageUsageVm` to carry real measured bytes, the optional
  percentage (only when a real budget exists), the active policy summary,
  and whether a warning is currently appropriate.
- Adds an expansion view model reading the latest decision pass — one entry
  per category with its bytes and its reason copy, plus the "Why" summary
  `FR-STORE-007` asks for.
- Renders the card's collapsed and expanded states in `dashboard_view.dart`
  against the contract.
- Registers what the controller needs in `dashboard_binding.dart` via
  `Get.find` of the permanent registrations `E08-T06` made in `AppBinding`.
- Runs the design gate and records the report verbatim.

## 4. What this task does NOT do  ← the scope fence
- **No "Clean Now", no delete affordance, no confirmation dialog, no
  swipe-to-clear.** Not even disabled. (`FR-STORE-006`, `EARS-STORE-2`.)
- **Does not trigger a retention pass, apply a plan, or call the executor.**
  Read-only on the storage domain.
- **Does not invent a denominator or render a percentage without one.**
- **Does not touch the Network Status card, the connectivity readings, the
  latency figure, or Recent Conversations** — `GAP-012`/`GAP-013` and
  `E06-T12` own those, they are already merged and already gated, and a
  drive-by edit there is out-of-scope work on merged code (rule 6).
- **Does not fix the delivery-tick colour-token divergence** across
  chat/dashboard/conversations (E06 retro §5). E07 declined it for the same
  reason and said so; E08 declines it again, on the record: it is a shared
  token across three screens and a standing S4 chore, not this card's work.
- **Does not swap a widget type to score better against the design probe**
  (`L-frontend-001`, now a rule). If a correct, accessible widget costs
  gate score, disclose the score.
- **Does not add a route, a settings screen, or mode-selection controls** —
  that is the prospective `E08-T09`, unshardable until `E08-T07` writes
  its contract.
- **Does not widen the probe fixture beyond** the dashboard storage-plan
  seed and the one group-conversation seed named in §2. The fixture fix is
  scoped, not an invitation to refactor the harness.
- Does not touch `lib/app/bindings.dart` (owned by `E08-T06`) or
  `lib/app/routes.dart`.

## 6. Risks
- The design measured `45% used`; without a denominator the built string
  differs. That is a **disclosed deviation with a spec reason**
  (`OQ-E08-1`), recorded in §9 and in `GAP-026` — not a silently changed
  string, and not a fabricated percentage.
- The dashboard is the app's front door and already carries three
  never-synthesize prohibitions. Adding a fourth number is the highest-risk
  place in the app to get "just show something" wrong.
- Editing the shared probe fixture can change **other screens'** gate
  scores. Re-run the gate for every screen the fixture feeds and record
  each before/after number, or a silent regression lands on a screen this
  task never opened.
- `Obx` over two independent Rx values (usage and expansion) rebuilds more
  than needed; keep the rebuild scoped or the card jitters on every tick.

**Deviations from spec/design:**

1. **The `45% used` string is an expected, disclosed deviation** —
   `storage_policy_settings.budget_bytes` is NULL by default (`OQ-E08-1`
   answered 2026-09-02, option (c) for this card), so the card renders the
   real measured byte total (`N MB used`) instead, per `GAP-026`'s
   approved record. Not a silent rewrite: `design/screens/dashboard.md`'s
   own §Derived state names this exact deviation.

2. **`Smart Mode - Older than 10 days` (element 18) becomes a real,
   data-driven summary line, another disclosed copy finding**, per
   `GAP-011`'s approved resolution ("static copy until E08 builds the
   retention policy it describes"). Smart Mode's parameter is
   `SmartModeThresholds.defaults().ageThresholdDays` (45, per `A-004`'s
   placeholder set) — the real value `SmartModePolicy` scores against, not
   an invented number. The two manual modes' summary lines
   (`_policySummaryText` in `dashboard_view.dart`) reuse
   `design/screens/settings-storage.md` SS11's own BRD-§19-verbatim mode
   names (this epic's sibling derived contract), substituting the user's
   real parameter for BRD's own "X" — a judgment call, since `dashboard.md`
   itself only measures the Smart Mode string; §5's own format-contract
   note ("the format is the contract, the number is data") is read as
   licensing this substitution rather than requiring new invented prose.
   Both manual modes are unreachable in this build without `E08-T09` (not
   yet sharded), so this branch is exercised only by direct unit
   construction of `_policySummaryKeyFor`'s output, not by any running UI
   path today.

3. **The "Will remove:" list is filtered, not `plan.groups` verbatim.**
   `SmartModePolicy.plan()` (E08-T04) scores `message`-kind items by
   age/access/size regardless of mode — the mode-dependent exclusion
   (`OQ-E08-3(a)`) is enforced downstream, by `StorageManager`/
   `RetentionExecutor`, not by the pure scorer. Showing `plan.groups`
   uncritically would let a Smart Mode user read "Will remove: Messages"
   for content that categorically will never be removed under their
   active policy — a false warning `FR-STORE-006`'s "informational"
   promise forbids, and the opposite of `dashboard.md`'s own stated
   reasoning for why `Nothing to remove right now.` is "the expected
   default reading" (`GAP-025`). `DashboardController._actionableGroups`
   mirrors the SAME two unconditional invariants
   `RetentionExecutor.apply` already enforces (relayPayload is always
   `RelayEngine`'s; Smart Mode never touches `message`) — not a new
   policy, read here for display consistency only. Flagged as a judgment
   call rather than a silent one: §2's "never re-implement policy in a
   widget" note is in tension with not showing a false warning, and I
   resolved it toward the latter since a false "your messages are at
   risk" reading is the more serious defect.

4. **`storagePressure`'s reason copy (`Storage running low`) has no
   approved source.** `dashboard.md`'s §Copy list gives copy for
   `olderThan`/`rarelyAccessed`/`noLongerRequired`/`overSizeLimit` but not
   for `storagePressure` (an open fork in both derived contracts' §Open,
   `OQ-E08-4`'s neighbourhood). Since `budget_bytes` is NULL by default,
   this branch is not reachable in this build's shipped configuration;
   the fallback string is a placeholder pending that fork's resolution,
   not presented as approved copy.

5. **The DX6 "plan's summary sentence" has no verbatim wording in the
   contract** — `dashboard.md`'s element table names it only as "(the
   plan's summary sentence)", with no string given anywhere in §Copy.
   Implemented as `Removing these would free up N MB.`, using only the
   contract's own established `N MB` format token and real data — a
   judgment call on wording the contract left open, not an invented
   figure.

    boundary, not at the first one encountered. A dedicated task should
    scope this, re-verify every screen's score before/after (the same
    discipline this task applied to the fixture seeds), and record the
