# E08-B05 · Two answered decisions, zero implementations, no owner

## The defect

**EARS-STORE-1**: *"WHILE Smart Mode is active, the system SHALL determine
removal candidates using the eight named factors."* Six ship. Two report
`Unavailable` on every call, and both have a human answer on record that
nobody built.

**1 · `storagePressure`.** `OQ-E08-1` is 🟢 answered
(`epic.md:105-109`): *"(a) device free space via Pigeon for the pressure
factor, + (c) the dashboard card shows real measured bytes"*. Half (c) was
built by T08. Half (a) was not:

- `pigeons/` contains only `transport.dart`; a repo-wide grep for
  `freeSpace|availableSpace|statfs` in `lib/` and `pigeons/` returns
  **nothing**.
- `StorageSettingsRepository.setBudgetBytes` (`:165`) has **zero callers**
  in `lib/`, so `budgetBytes` is permanently NULL.
- Therefore `smart_mode_policy.dart:129-133` always takes the
  `FactorScore.unavailable('OQ-E08-1 — no storage budget ...')` branch, and
  the whole storage-pressure reason-override branch
  (`smart_mode_policy.dart:241-247`) is dead code — flagged as
  untested-but-live by T04's own reviewer, and in fact unreachable.

**2 · `importance`.** `OQ-E08-4` is 🟢 answered (`epic.md:190-193`):
*"(a) — derive from a Trusted relationship (E02) plus a never-delete rule
for undelivered messages"*. The undelivered half is built
(`retention_executor.dart:136-140`, EARS-STORE-14). The Trusted-relationship
half is not, and the code still asserts the question is open:

```dart
// lib/core/storage/smart_mode_policy.dart:147-149
const importanceFactor = FactorScore.unavailable(
  'OQ-E08-4 — "importance" is not a defined term in this build',
);
```

That string is now factually wrong — the term *was* defined, by the human,
on 2026-09-02.

## Repro
1. `grep -rn "setBudgetBytes" lib/` → one declaration, no call sites.
2. `grep -rniE "freeSpace|availableSpace|statfs" lib/ pigeons/` → no matches.
3. Run any Smart Mode pass and read `plan.unavailableFactors` — it contains
   `storagePressure` and `importance` on every device, unconditionally.

## Expected
FR-STORE-005 / EARS-STORE-1 — eight factors. Rule 1: a human answer to a
blocking question is as binding as the spec. FR-STORE-007 — the explanation
surface names why each factor did what it did; two of eight can only say
"unavailable", citing questions that are in fact answered.

## Actual
Six of eight factors scored. Two permanently `Unavailable`, each with a
reason string that cites an answered question as if it were open.

Critically, **nothing at epic level carries the obligation**: the
tracker's "Still open, non-blocking" list names only `OQ-E08-T05-1` and
`OQ-E08-T08-2`; §Carried-forward observations names neither of these. The
only record is `OQ-E08-T04-3`, buried in `E08-T04.md`'s §Open Questions —
which is exactly the read-by-nobody position `L-process-008` was promoted to
a rule to prevent, after E06's `E06-B02` sat unread for eight tasks.

## Severity
**S3** — the epic's headline criterion is partially unmet and the code
misstates the spec's own state, but the degradation is *honest*: both
factors report `Unavailable` rather than a fabricated `0.0` (T04's reviewer
falsified this specifically), so nothing downstream is fed a synthesized
measurement and E04-B03's prohibition is intact. Smart Mode still produces
a usable plan from six real factors. Not S2: no function is broken, it is
incomplete — and the incompleteness is disclosed everywhere except where it
needed to be.

## Fix direction
This is a **planner** item before it is a builder item.
1. **Immediately, and independent of any code:** record both obligations in
   `epics/E08-local-storage/tracker.md` §Carried-forward observations, so
   they have a reader. The sweep has done this; the tracker entry is the
   durable half of this bug's fix.
2. **`storagePressure`:** `OQ-E08-1(a)`'s Pigeon free-space channel is a
   real native surface on two platforms — ADR-0004 already authorises Pigeon,
   so it is not a new-dependency gate, but it is a task of its own, not a
   patch. Until it exists, `budgetBytes` stays NULL and the factor stays
   honestly `Unavailable`. The `budgetBytes == 0 -> pressureRatio 1.0`
   branch (`smart_mode_policy.dart:135-137`, T04 review's S3 finding) must
   be settled in the same pass — a zero denominator is undefined, not "100%
   full".
3. **`importance`:** `OQ-E08-4(a)`'s Trusted-relationship derivation reaches
   into E02's relationship code, which is outside every E08 fence by design.
   Scope it as its own task with E02 in its `files:` fence.
4. **In any case, correct the reason strings now** — a factor that says
   *"is not a defined term in this build"* about a term the human defined is
   a lie the explanation surface tells the user. Cheap, in-fence, and does
   not wait on either build above.

## What this fix does NOT do
- Does **not** invent a budget default, a free-space number, or an
  importance heuristic. Both answers name a mechanism; neither supplies a
  value an agent may choose. Rule 3.
- Does **not** default either factor to `0.0` or to any score. They stay
  `Unavailable` until genuinely measured (E04-B03's prohibition, re-verified
  by T04's reviewer).
- Does **not** change the six working factors, the `A-004` threshold
  placeholders, or Smart Mode's empty allow-list.
- Does **not** build the Pigeon channel or the E02 derivation inside this
  bug task — step 4 (the reason strings) plus the tracker record are its
  in-fence deliverable; steps 2 and 3 are separate, scoped tasks.
