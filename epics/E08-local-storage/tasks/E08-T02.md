# E08-T02 · Storage inventory read model

## 1. Goal
Give the rest of the epic one honest answer to "what is actually stored on
this device, in what classes, and how many real bytes does each take" — so
every policy, warning and explanation downstream is computed from measured
data rather than from an estimate someone invented.

## 2. Business logic
- **Only real, measured bytes. Never a synthesized figure.** This is
  E04-B03's standing prohibition, restated by `dashboard_controller.dart`'s
  own header and enforced across E06's whole dashboard. A class whose size
  cannot be measured is reported as *unmeasured*, not as `0`.
- **Never decrypt, never parse a payload.** `messages.ciphertext` and
  `relay_packets.payload` are opaque bytes (FR-ROUTE-003, NFR-PRIV-001).
  The inventory measures their **length**. It never calls into
  `CryptoService`, never deserializes a `MessageEnvelope`, and never logs a
  payload or a preview.
- **The item kinds that exist in this build, and only those.**
  `StorageItemKind` enumerates: `message` (a `messages` row's ciphertext),
  `relayPayload` (a `relay_packets` row's non-NULL payload),
  `databaseFile` (the sqlite file's own on-disk byte size). Media kinds
  (`voiceMessage`, `pttRecording`, `callRecording`, `attachment`) are
  declared in the enum **and documented as producing zero items today**,
  because nothing in this build writes them (see §6 and `OQ-E08-6`) — the
  enum is the seam the prospective media-path task extends, not a promise
  that data exists.
- **`isTemporary` is derived, not invented.** A `relayPayload` is temporary
  by construction (`relay_tables.dart`: "local only, ephemeral", TTL owned
  by `RelayEngine.reclaimPayloads`). A `message` is not. The BRD's
  "Temporary cache" category (§20) maps to `relayPayload`, and this is the
  definition the rest of the epic uses for the eight factors' *temporary
  status* input.
- **Reading is cheap and bounded.** Sizes come from SQL aggregates
  (`SUM(LENGTH(ciphertext))`, `COUNT(*)`), not from loading every row's
  bytes into Dart. A history large enough to be worth managing is a history
  too large to materialize.

## 3. What this task does
- `storage_item.dart`: the `StorageItemKind` enum, an immutable
  `StorageItem` (kind, id, conversationId?, bytes, createdAt, isTemporary)
  and an immutable `StorageClassTotal` (kind, itemCount, bytes).
- `storage_inventory.dart`: `StorageInventory`, reading `AppDatabase` and
  the sqlite file path, exposing per-class totals, a bounded per-item
  listing for a given kind, and the on-disk database file size.
- A `StorageInventorySnapshot` value carrying the class totals, the
  database file size, and a `measuredAt` stamp.
- Tests over a real in-memory `AppDatabase` with seeded rows.

## 4. What this task does NOT do  ← the scope fence
- **Deletes nothing.** Not one row, not one file. This task is read-only
  over user data, permanently.
- **Does not compute a percentage, a quota, or a "pressure" reading.**
  There is no denominator yet (`OQ-E08-1`); inventing one here is exactly
  the fabricated-figure defect `dashboard_controller.dart` was written to
  avoid.
- **Does not touch relay TTL or `reclaimPayloads`.** E04-B02 owns relay
  payload retention and `E06-T06`'s coordinator already drives it. The
  inventory *reports* relay bytes; it does not reclaim them, reschedule
  them, or second-guess their TTL.
- **Does not record access signals.** `storage_item_stats` is written by
  `E08-T03`; this task does not read or write it.
- **Does not add a media capture path.** No recorder, no file writer, no
  `path_provider` directory for media. The media kinds are enum values with
  no producer, and that stays true here.
- Does not touch `dashboard_controller.dart` — the UI wiring is `E08-T08`.
- Does not widen `ConversationRepository` or any E05/E06/E07 read model.

## 5. Contract

### Functions
```yaml
- signature: "StorageInventory({required AppDatabase db, required Future<int> Function() databaseFileBytes})"
  params:
    db: "the app's single AppDatabase instance (composed by E08-T06, never constructed here)"
    databaseFileBytes: "injected measurement of the sqlite file's on-disk size; injected so tests need no real file and so the real implementation's dart:io call is a caller concern"
  returns: "StorageInventory"
  purpose: "read-only inventory over locally stored data"

- signature: "StorageInventory.snapshot() -> Future<StorageInventorySnapshot>"
  params: {}
  returns: "StorageInventorySnapshot — per-kind totals + database file bytes + measuredAt"
  purpose: "the one call every policy and every UI surface reads"

- signature: "StorageInventory.itemsOfKind(StorageItemKind kind, {int limit = 500, int? olderThanEpochMs}) -> Future<List<StorageItem>>"
  params:
    kind: "which class to enumerate"
    limit: "hard bound; the caller pages, the inventory never returns an unbounded list"
    olderThanEpochMs: "optional createdAt filter, pushed into SQL"
  returns: "List<StorageItem>, newest first; empty for a kind with no producer"
  purpose: "per-item enumeration for candidate selection, bounded by construction"

- signature: "StorageInventory.totalBytes(StorageInventorySnapshot snapshot) -> int"
  params: { snapshot: "a snapshot from snapshot()" }
  returns: "sum of measured class bytes; the database file's own size is reported separately and NOT double-counted here"
  purpose: "the numerator every later surface uses — the denominator is OQ-E08-1's"
```

### Data
Reads only. `messages(id, conversation_id, created_at, LENGTH(ciphertext))`,
`relay_packets(id, created_at, LENGTH(payload) WHERE payload IS NOT NULL)`.
No writes, no migration.

## 6. Risks
- `LENGTH()` on a BLOB in SQLite returns bytes; on TEXT it returns
  characters. Both columns here are BLOBs — assert it in a test rather than
  trusting it, because a future column change would silently make every
  figure wrong.
- The sqlite file's own size is **not** the sum of row payloads (pages,
  free space, WAL). Reporting both and never summing them is deliberate;
  a reviewer should check nothing adds them together.
- `relay_packets.payload` is nullable since v10 — a reclaimed row has a row
  but no bytes. Counting it as an item with `bytes: 0` overstates the item
  count; excluding it understates diagnostics. This contract **excludes**
  NULL-payload rows from `relayPayload` items and says so in the code.
- The media kinds have no producer today. A test asserting they yield zero
  items is the honest regression guard — and the thing that will fail
  loudly, in a useful way, the day the media path lands.

## 8. Acceptance criteria (EARS) + test plan
- **EARS-STORE-5**: WHEN the inventory is snapshotted, the system SHALL
  report, per storage class, the real measured byte total and item count of
  what is stored locally. (FR-STORE-001, FR-STORE-005)
- **EARS-STORE-6**: The inventory SHALL never decrypt, parse or log a
  stored payload, and SHALL report a class it cannot measure as unmeasured
  rather than as zero. (NFR-PRIV-001, FR-ROUTE-003)

### Tests
- `test_EARS_STORE_5_snapshot_reports_measured_message_bytes` → seeded
  ciphertexts of known lengths; totals match exactly.
- `test_EARS_STORE_5_relay_rows_with_null_payload_are_not_items` →
  reclaimed rows contribute neither bytes nor item count.
- `test_EARS_STORE_5_media_kinds_yield_zero_items_today` → the four media
  kinds return empty; documents the seam.
- `test_EARS_STORE_5_database_file_size_is_reported_separately` → not
  included in `totalBytes`.
- `test_EARS_STORE_6_inventory_never_decrypts` → grep-style source
  assertion plus a fake `AppDatabase` whose ciphertext is undecryptable
  garbage; the snapshot still succeeds.
- `test_EARS_STORE_6_items_of_kind_respects_limit` → a seeded set larger
  than `limit` returns exactly `limit` rows.
