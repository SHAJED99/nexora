# E06-B01 · devices_view.dart RenderFlex overflows

## 1. How this was found
E06-T01 (the Flutter-capable design-fidelity gate) pumps `DevicesView` with
one seeded row of each `RelationshipState` (trusted/allowed/unknown/blocked)
at the contract viewport (390×844) and walks the rendered tree. Doing so
triggers **two real `RenderFlex` overflow errors**, not a design-fidelity
mismatch:

1. `devices_view.dart:220` — the per-device badge `Row` (icon + badge label +
   `Spacer()` + either an "unknown"-state `Verify` button or a `Last seen:
   ...` text) overflows by **57px** on at least the `unknown`/other states —
   the trailing content after `Spacer()` has no width bound, so it can be
   wider than the space actually left over.
2. `devices_view.dart:336` (`_BottomNav`'s `build`) — the four `_NavItem`s in
   a `mainAxisAlignment: spaceBetween` `Row` overflow by **183px** — each nav
   item's icon+label column has no flex, so their combined natural width can
   exceed the available width with no way to shrink.

Critically, this is not merely a cosmetic finding: reproducing it under
`flutter test` causes the pump/layout cycle itself to hang for the
framework's full default 10-minute per-test timeout (confirmed by the
orchestrator directly, `epics/E06-personal-chat/tracker.md` event log,
2026-08-30) — something in repeated failed-relayout painting of the overflow
indicator does not return control to the test harness in reasonable time.
This blocks E06-T01's own proving screen and would hang `make design-probe`
outright once `devices` is registered. It is a genuine implementation bug in
an already-merged screen (E02-T02), not a task E06-T01 may fix inside its
own diff (out of that task's `files:` fence) — hence this separate bug task,
which `E06-T01` depends on (blocks) rather than works around a second time.

## 2. What this task does
- Fix **both** overflows so `DevicesView` lays out cleanly at 390×844 with
  all four `RelationshipState` rows present, with **zero** `FlutterError`
  recorded during `pumpAndSettle` — this is the acceptance bar, verified by
  a widget test that asserts `tester.takeException()` is `null` after
  pumping all four states.
- Badge row (`:220`): make the trailing content (the `Verify` button or the
  `Last seen: ...` text) share the row's available width honestly instead of
  assuming it always fits — e.g. wrap it in `Flexible`/`Expanded` as
  appropriate, and give the `Last seen: ...` `Text` an overflow policy
  (`TextOverflow.ellipsis`) so a long relative-time string degrades
  gracefully instead of overflowing. The `Verify` button's existing
  `BoxConstraints(minWidth: 56, minHeight: 24)` stays a *minimum*; wrapping
  it in `Flexible` does not need to change that.
- Bottom nav (`:336`): give each `_NavItem` equal flex (`Expanded`) instead of
  a bare, unconstrained natural width in a `spaceBetween` `Row` — the
  standard fix for a fixed-count icon+label bottom nav.
- **This is a layout-only fix.** Do not change any copy, icon, color, font
  token, spacing constant, or the four `RelationshipState` → visual mapping.
  `make design-verify SCREEN=devices IMPL=flutter` (once E06-T01 lands) must
  still show zero *new* copy/style/token findings versus what T01 itself
  records as pre-existing (GAP-003's placeholder subtitle, etc.) — this task
  only makes the existing design render without erroring, it does not chase
  fidelity.
