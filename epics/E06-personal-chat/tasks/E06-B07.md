# E06-B07 · Fix the `chat` design-probe fixture so `design-verify SCREEN=chat` can actually pass

## The gap (design-fidelity skill rule 6 — L-design-002 pattern)
`make design-verify SCREEN=chat IMPL=flutter` has never been green, and is
not close: `❌ FAIL — 79.1% (34/43)`, with `9` missing elements, `16` copy
mismatches, `114` style deltas, and `2` off-palette tokens, on the `chat`
probe fixture (`test/design/design_probe_test.dart`'s `screen probes — chat`
group) as it exists today. This has been **disclosed, correctly, at least
three times** without ever being fixed — most recently in `E06-B06`'s own
Review round 1, which explicitly flagged (F4) that "declining to seed the
fixture was correct... but rule 6 asks for an explicitly-scoped fixture-fix
task rather than another prose note. Another prose note is what was
written," and noted this is now the third task to hit the wall (after the
`conversations` screen's own `E07-T08`/`E07-B01` history, per the
design-fidelity skill's own file). This task exists so a fourth reviewer
does not have to re-discover the same thing a fourth time.

## What's actually wrong, as measured (not yet root-caused past this)
`test/design/design_probe_test.dart`'s `chat` fixture (`setUp`) seeds one
trusted peer (`device-trusted`) with **5** plain-text messages, deliberately
undecryptable in the test environment (no real Signal session is ever
established between the probe's synthetic device ids) — per that fixture's
own comment, the resulting `(unable to decrypt this message)`/`(empty)`
placeholder text is treated as an accepted, disclosed limitation, not
something to fake around. Two things beyond that comment's own disclosure
are NOT yet explained and are this task's job to run down:
1. `design/screens/chat.md`'s golden capture shows **8** message-area
   elements (10-25), including a file-transfer bubble (elements 16-18,
   `troubleshoot`/`Backup: Family Photos`/`In progress... 78%`) that this
   screen's own `GAP-010` already establishes is data-driven content this
   codebase doesn't build — so golden vs. build were never going to line up
   1:1 on message content, and that much is expected. What is **not**
   explained: the golden's `more_vert`, `add`, and `mic` icons — real,
   already-built, always-rendered elements in `chat_view.dart` (`_Header`'s
   overflow icon; `_Composer`'s `+`/mic) — show up in the report's "❌ Copy
   mismatches" table as `absent` (not merely mismatched), meaning the probe
   dump did not find them in the build AT ALL. Given these elements exist
   unconditionally in the widget tree, the leading hypothesis is that the
   probe's fixed `390×844` test viewport, combined with the 5-message
   thread's total rendered height, pushes them outside whatever bounds the
   probe dumper walks — but this is a hypothesis, not yet confirmed; verify
   from scratch rather than assuming it.
2. Whether seeding the fixture with 8 messages (matching golden's count,
   including a stub/placeholder file-transfer row if one can be built
   without faking GAP-010's own already-accepted non-rendering) changes the
   missing-element count at all, isolating whether root cause #1 is really
   a viewport/overflow issue or something else.

## What this task does
1. Investigate why `more_vert`/`add`/`mic` are absent from the probe dump
   despite being unconditionally rendered — confirm or refute the
   viewport/overflow hypothesis above with actual evidence (e.g. dump the
   probe's raw element list and check for a total content height exceeding
   844, or instrument the dumper itself if needed within this file's own
   fence).
2. Bring the fixture's seeded message count/shape closer to
   `design/screens/chat.md`'s golden (8 messages) where doing so doesn't
   require faking anything this codebase doesn't actually build (GAP-010's
   file-transfer bubble stays unrendered; do not invent a fake one just to
   pad the count unless a real, honest stub is possible).
3. Re-run `make design-verify SCREEN=chat IMPL=flutter` and record the
   before/after finding counts honestly — this task's Definition of Done is
   **not** "the gate is green" (the copy/style mismatches from undecryptable
   placeholder text may be a genuine, permanent, disclosed limitation of
   testing a real end-to-end crypto path without a real session) but *is*
   "every remaining ❌/⚠️ is understood and disclosed with a specific reason,
   not an open question."

## What this task does NOT do
- Does NOT touch `chat_view.dart`, `chat_controller.dart`, or any other
  production file — this is a test-fixture-only task.
- Does NOT fake or hardcode decrypted message text to force a copy match —
  that would hide a real limitation (this environment cannot establish a
  real Signal session) behind a green gate, which is worse than a disclosed
  red one.
- Does NOT render `GAP-010`'s file-transfer bubble for real — that gap's
  own resolution (a real data-driven file-transfer feature) is out of this
  task's scope entirely.
- Does NOT touch any other screen's probe fixture, even if the same
  viewport/overflow root cause (if confirmed) turns out to affect them too
  — file a new, separately-scoped task per screen affected, per the same
  rule 6 discipline this task itself exists to honor.
