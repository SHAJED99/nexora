# E06-T15 · Localization resources + logical RTL geometry

> **Why this task exists.** `FR-UI-005` has been baselined since genesis and
> has **no implementation at all** — no `lib/l10n/`, no `l10n.yaml`, no
> localization mechanism of any kind, and every visible string is a literal.
> It is one of `make trace`'s ten `requirement with no test` orphans. Found by
> the 2026-09-24 product-completeness audit.
>
> **What it is not.** This does not add a second language, and it does not make
> the app more usable for an English-speaking user. It discharges a stated
> requirement and gives every later string one place to live. Said plainly so
> nobody reads the merge as "the app is now localized".

## 1. Goal
Every visible string in the settings area comes from a localization resource
reached as `context.l10n.<key>`, and directional geometry is expressed
logically, so an RTL locale lays out correctly rather than mirror-broken.

## 2. Business logic
Implements `FR-UI-005`: *"All visible strings shall come from localization
resources; the UI shall support RTL layout via logical (not literal
left/right) padding."*

- The shape is fixed by `documentation/Design.md` §111, which gives the call
  site verbatim: `Text(context.l10n.updateRequired)`. So: a `context.l10n`
  extension on `BuildContext`, not a global singleton and not `Get.find`.
- §112 fixes the RTL shape: prefer `EdgeInsetsDirectional.only(start: …)` over
  `EdgeInsets.only(left: …)`.
- **No new package.** `intl` adds pluralization and date/number formatting;
  `FR-UI-005` asks for neither. `Directionality` and `EdgeInsetsDirectional`
  are core Flutter. Adding a dependency here would be a rule-3 gate for
  capability this requirement does not ask for.
- **Not one string may change.** Every one of these screens is measured by an
  approved design contract, and all ten currently pass `make design-verify` at
  **100%**. A copy change is a hard gate failure. That gate is this task's
  regression test.

## 3. What this task does
- Adds `AppStrings` — one class, one getter per string, and a
  `BuildContext.l10n` extension returning it.
- Migrates every visible string in **two** settings views to
  `context.l10n.<key>`, byte-for-byte unchanged: the hub (every hard case)
  and the sign-out confirmation (the simple case). The other eight are
  `E06-T16`.
- Converts literal directional geometry in those files to logical equivalents:
  `EdgeInsets.fromLTRB` → `EdgeInsetsDirectional.fromSTEB`,
  `Alignment.centerLeft` → `AlignmentDirectional.centerStart`,
  `TextAlign.left` → `TextAlign.start`.
- Adds tests, including one that renders a settings screen under
  `Directionality(textDirection: TextDirection.rtl)` and asserts it lays out
  without overflow.

## 4. What this task does NOT do  ← the scope fence
- **Does NOT add a second locale, `intl`, `flutter_localizations`, `.arb`
  files, or `l10n.yaml`.** Those are how this grows later; none is required by
  `FR-UI-005` as written, and each is a rule-3 `new_dependency` call.
- **Does NOT change a single rendered string.** Not a capital, not a full stop.
  Ten approved design contracts measure this copy verbatim.
- **Does NOT migrate the rest of the app.** `dashboard`, `conversations`,
  `chat`, `devices`, `welcome`, `login`, `groups`, `recovery` and `version`
  are a follow-up. They are deliberately excluded because four of them
  (`chat`, `devices`, `conversations`, `dashboard`) currently **fail** the
  design gate, so a copy regression there would be invisible — the gate cannot
  distinguish a new failure from the existing one. Migrating them belongs
  after **P9** triages those deltas.
- **Does NOT close `FR-UI-005`.** The requirement closes when the last area is
  migrated. This task's own `traces_to:` does not let it claim otherwise, and
  the follow-up task is named in §9.
- Does NOT touch controllers, repositories or any backend file.
- Does NOT reorder, reformat or "tidy" the migrated files beyond the string
  and geometry substitutions. A large mechanical diff must stay mechanical, or
  the reviewer cannot tell substitution from edit.

## 5. Contract

### Functions
```yaml
- signature: "AppStrings.of(BuildContext context) -> AppStrings"
  params: { context: "the element's context" }
  returns: "AppStrings — the active string table"
  purpose: "one resolution point, so a later locale lookup changes one line"
- signature: "BuildContextL10n.l10n -> AppStrings"
  params: {}
  returns: "AppStrings"
  purpose: "the call shape Design.md 111 specifies verbatim"
```

### UI
- **Gate:** both migrated screens (`settings`, `sign-out-confirm`) must still report
  `PASS … match 100%` from `make design-verify SCREEN=<id> IMPL=flutter`
  **after** the migration. Any drop is a copy regression.

### External services & flags
None. **No new dependency.**

## 6. Risks
1. **A single altered character fails an approved contract.** The copy is
   measured. Migrate by moving the literal verbatim into the getter, never by
   retyping it.
2. **`EdgeInsets.fromLTRB` → `fromSTEB` is not a rename.** The argument order
   differs in meaning: `fromLTRB(l, t, r, b)` vs `fromSTEB(start, top, end,
   bottom)`. Under LTR they coincide; a careless swap is invisible in every
   test that does not run RTL. That is why §3 requires an RTL render test.
3. **`TextAlign.left` → `TextAlign.start` changes rendered alignment under
   RTL only.** Correct, and invisible to the LTR design gate.
4. **A string used in two places must not become two getters**, or a later
   copy change updates one and not the other.

## 8. Acceptance criteria (EARS) + test plan

- **EARS-UI-12**: WHERE a settings screen renders a visible string, the system
  SHALL obtain it from a localization resource rather than a literal at the
  call site. (`FR-UI-005`)
- **EARS-UI-13**: WHEN a migrated screen is rendered under an RTL text
  direction, the system SHALL lay it out without overflow and SHALL mirror
  directional insets. (`FR-UI-005`)
- **EARS-UI-14**: WHERE a string is shown on more than one screen, the system
  SHALL resolve it from exactly one localization key. (`FR-UI-005`)

### Tests
- `test_EARS_UI_12_settings_views_contain_no_user_facing_literals` → scans the
  ten migrated files' source and fails on a remaining capitalised literal,
  with an allowlist for non-user-facing strings (route names, keys, semantic
  identifiers) that names each exemption.
- `test_EARS_UI_13_settings_renders_under_rtl_without_overflow` → pumps the
  settings hub inside `Directionality(textDirection: TextDirection.rtl)` and
  asserts `tester.takeException()` is null.
- `test_EARS_UI_13_directional_insets_mirror` → asserts
  `EdgeInsetsDirectional.fromSTEB(...).resolve(TextDirection.rtl)` mirrors,
  proving the conversion is logical rather than a rename.
- `test_EARS_UI_14_shared_strings_resolve_to_one_key` → asserts no two getters
  return an identical string.
