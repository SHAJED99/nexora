# E06-B08 · Fix the Flutter design-probe dumper's icon-swallowing and icon-name gaps

## Where this came from
`E06-B07` (fix the `chat` design-probe fixture) root-caused, for the first
time down to an exact code path (not just inferred from a score delta), why
`more_vert`/`add`/`mic` show as flatly ABSENT from the `chat` probe dump —
see that task's Run log §1 for the full investigation and evidence
(`build/design-probe/chat.json` raw dump). This is `L-frontend-001`
(`agent/memory/lessons/frontend.md`) — the SAME probe-tooling capability gap
already named at E06-T10 (2026-08-30) and hit again at E07-T08/B01 and
E08-T08 — but `E06-B07`'s own `files:` fence only allowed touching
`test/design/design_probe_test.dart`, not this dumper file, so per
design-fidelity skill rule 5/6 it was disclosed there and filed here as its
own scoped task, rather than fixed in place or left as another prose note.

## What's actually wrong
`test/design/flutter_probe_dumper.dart`'s `_walk` function has two distinct
defects, both making the Flutter probe path under-report real, rendered
content relative to the DOM-based golden (`design/tools/lib/probe.mjs`):

1. **Nested icon glyphs inside an interactive wrapper are never emitted.**
   When `_isInteractive(widget)` is true (an `InkWell`/`IconButton`/etc.),
   `_walk` emits exactly one `button`-role element (its `text` from
   `_collectText`, which only ever collects `Text` descendants) and then
   recurses into the widget's children with `insideInteractive: true`. The
   `Icon` branch only adds a probe element when `!insideInteractive` — so
   an icon-only tap target (no `Text` label, just an `Icon`, e.g.
   `chat_view.dart`'s `_IconTapTarget`/`_RoundIconButton`, and the
   equivalent pattern on `devices`/`conversations`/`dashboard`/every
   `settings-*` screen) dumps as ONE element with empty text — its icon
   glyph is never captured at all. The golden always captures an icon-font
   glyph as its own nested element (a `<span>` inside the `<button>` in the
   source DOM), so this is a structural under-count relative to the golden
   on every screen with an icon-only button, not a chat-specific issue.
2. **`_iconNames` is missing `Icons.check` and `Icons.done_all`.** These are
   used by `chat_view.dart`'s own delivery-tick glyphs
   (`_tickIconFor`) and are NOT nested inside an interactive wrapper (bare
   `Icon`s), so they ARE walked and DO get a probe element — but
   `_iconName()` returns `null` for their `codePoint`, so the element dumps
   with empty `text`, reading as a copy mismatch rather than a match.

## What this task does
1. Fix defect 1: when `_walk` encounters an `Icon` widget while
   `insideInteractive` is true, emit it as its own probe element (same
   shape as the `!insideInteractive` case), rather than silently dropping
   it — mirroring the golden's own "icon glyph is a separate nested
   element" model. Do this without breaking the EXISTING, correct
   suppression of a genuinely separate nested interactive target
   (`_isInteractiveBoundary`) — an icon inside a nested `IconButton`/
   `TextButton`/etc. two levels down must still resolve to that inner
   button's own element, not double-emit.
2. Fix defect 2: add `Icons.check` and `Icons.done_all` to `_iconNames`.
   Audit the rest of the map against every `Icons.*` constant actually used
   under `lib/` (not just chat's) for the same kind of gap while in this
   file, and add any other missing entries found — but do not invent
   ligature names not already established by this map's own existing
   convention (one entry per `Icons.*` constant this app's own code
   actually uses).
3. Re-run `make design-probe` then `make design-verify SCREEN=<id>
   IMPL=flutter` for every screen this file registers (`chat`, `devices`,
   `conversations`, `dashboard`, every `settings-*`, etc.) and record each
   screen's before/after finding counts in this task's Run log — some
   screens may newly show EXTRA findings if this fix changes total element
   counts in a way that shifts other comparator pairings; disclose those

4. Update the EARS-UI-1/2 falsification tests in
   `test/design/design_probe_test.dart` if this fix changes their expected
   element counts — but only that file's OWN test expectations, not its
   screen fixtures (out of this task's scope; each screen's fixture is
   owned by its own screen's task).
